## [1.1.0] - 2026-09-24

First public release (repo: `moyetian/Kaoyan_chain_Bench`). Two hardening rounds on top of v1.0;
the public repo **contains no private hidden tasks** (see below).

### Added

- **Snapshot library completed (synthetic mirrors)**: all 23 online tasks ship offline-replay
  **synthetic mirror snapshots** (35 pages of fictional replay corpora for `--offline-replay` link
  verification — not real web pages; real snapshots still await `snapshot fetch` capture and
  versioning), deterministically generated by `tools/build_snapshots.py` (verifiable with
  `--check`); `validate --require-snapshots` errors on missing snapshots; enforced in nightly and
  smoke CI.
- **Private hidden-set mechanism**: `tools/build_private_tasks.py` (10-task generator is public),
  `--split private` isolation, private-solvability tests. **The tasks themselves are never committed**
  (gitignored; `tests` auto-skip when absent), generated and run only in controlled environments.
- **Regression comparability gate**: `grader_mode` mismatch (full vs degraded) appends a warn gate —
  scores containing degraded grading no longer compare silently.
- **Reproducible report metadata**: `SuiteResult.source` gains `git_sha` + `trace_schema_version`.
- **`Run` records effective budgets**: `time_limit` / `tool_limit` persisted; `grade --run-id`
  re-grades with identical caliber as first grading.

### Changed

- **Budget priority fixed to CLI > suite.defaults > task > global** (previously task always won and
  `suite.defaults` was dead config; smoke's 120s/30 and core50's 900s/100 now actually apply).
- **Degraded-score cap**: `fallback_semantic_score` capped at 0.7 — degraded can no longer pose
  as full.
- **Smoke-set description fixed**: smoke is 5 categories / 6 tasks (previously mislabeled
  "covers 8 categories").

### Fixed

- **Leak-proof isolation**: the `{task_dir}` template variable and `KAOYANBENCH_TASK_DIR` env var no
  longer expose the real task directory (redirected to the workspace isolation dir) — agents can no
  longer read `task.json` directly to cheat; old configs stay compatible.
- **Replay sources stuck at E0**: under `--offline-replay`, snapshot sources skipped evidence-rule
  adjudication so `source_level` always failed; replay sources are now re-adjudicated by the rules
  (E0 → E4/E5) and the snapshot library is genuinely usable.
- **Windows console crash**: printing `✅/❌` on GBK terminals raised `UnicodeEncodeError` and killed
  whole runs; now degrades to `[OK]/[FAIL]` (Chinese text and JSON validity unaffected).
- **Cross-platform byte stability of generators**: `build_private_tasks.py` writes bytes (Windows
  text mode `\n→\r\n` used to break every manifest sha256); `string_contains` accepts only the
  single `value` (previously misused `any_of`).

### Notes

- Public-repo policy: private tasks are never committed; the `mock` Runner has no private presets
  (scoring 0 on private is expected).
- Repo: `https://github.com/moyetian/Kaoyan_chain_Bench`.

## [1.0.0] - 2026-09-23

KaoyanBench v1.0.0 — first public release of the grad-exam-scenario AI agent benchmark.
**Zero third-party dependencies on the core pipeline** (pure Python stdlib), Python ≥ 3.10.

### Added

- **CLI**: `kaoyanbench` (alias `kyb`), subcommands
  `list / run / grade / report / compare / regression / validate / fixtures / snapshot / suite / agent`;
  contract in design §5.10.
- **Task suite `core50`**: 50 tasks / 8 categories (search 12, university 9, policy 5, exam 5,
  pdf 5, planning 5, research 4, hallucination 5); Easy 10 / Medium 18 / Hard 15 / Expert 7.
- **Task suite `smoke`**: 6 fully-offline deterministic smoke tasks for CI and "running in
  30 seconds".
- **Runners**: `echo` / `mock` (offline canned answers) / `command` (argv templates + stdin/cwd/env/
  timeouts/three-level parsing) / `http` (OpenAI-compatible endpoints).
- **Sandbox (process-level isolation)**: isolated workspace, env allowlist (no `*_API_KEY` passed
  through by default), `HOME/TMPDIR/XDG` redirection, timeout SIGTERM→SIGKILL.
- **Grader**: `deterministic` / `semantic` (incl. SemanticClient) / `hybrid` / `manual`; 16
  declarative check types; E0–E5 evidence levels.
- **Scorer / Metrics**: 100-point 7-dimension scoring, 11 key metrics, category/difficulty grouping,
  Pass@1/Pass@3.
- **Report layer**: JSON (source of truth) / Markdown / single-file HTML (inline CSS/JS/SVG,
  **zero external requests**) / CSV.
- **Regression**: `compare` + `regression` gates (pp caliber) + exit codes 0/1/2.
- **Snapshots**: `snapshot fetch` (needs network) / `snapshot verify`; `--offline-replay`
  (L1 grading-layer replay, issues no network requests).
- **Store**: JSONL ↔ SQLite idempotent sync; SQLite is a derivative, `rm` and rebuild any time.
- **CI (C-04)**: `.github/workflows/{validate,smoke,nightly}.yml`
  - PR/push: `validate` (pytest + `validate --suite core50`, offline), `smoke`
    (`run --suite smoke --agent mock` + reports + regression gate).
  - nightly: full `core50` (with `--concurrency`) + report artifacts.
- **Deployment assets**: `.env.example`, `Dockerfile`, `.dockerignore`, `tools/release_check.sh`.
- **Docs**: `docs/03` (new-agent onboarding) / `docs/04` (report fields) / `docs/05-roadmap` /
  `docs/06` (deployment) / `docs/07` (go-live checklist) / `docs/08` (rollback plan), this CHANGELOG.
- **Observability**: `sandbox.sensitive_env_warnings` (warnings for sensitive `env_passthrough`
  vars), `ResultStore.resolve_suite_ref` (agent/tag reverse lookup for report commands).

### Changed

- Report layer completed from skeleton to all four formats JSON/Markdown/HTML/CSV.
- `validate` now **aggregates** every task's validation errors (incl. unloadable tasks) in one pass
  instead of dying on the first bad task.
- Baseline discriminability remediation: verdict words removed from instructions, echo pass rate
  28% → 0/50; `anti-echo` check warnings 84 → 0.
- `grade` subcommand fixed (reuses `utils/mini_yaml` restricted-parser semantics; `error_codes`
  extracted from `errors`).

### Fixed

- **Wrong CI directory name**: repo root once had `_.github/` (GitHub Actions only recognizes
  `.github/`), so the `validate` / `smoke` / `nightly` workflows **never triggered**. Renamed to
  `.github/`.
- **Default agent fallback error in report commands**: without explicit `--agent`, `report` /
  `compare` / `regression` treated the config-semantics `agent.ref` as a result-lookup key, so the
  README's front-page example `kaoyanbench report --suite smoke --tag smoke-1` failed outright.
  Now "explicit > config ref (only when results exist) > reverse lookup from existing results",
  erroring explicitly on ambiguity instead of guessing.
- **`suite.defaults` was dead config**: `core50.yaml` declared `defaults.runs: 3` with zero
  consumers — measured `runs_per_task=1`, Pass@3 silently dead. Now merged as
  `explicit CLI > task-level > suite.defaults > global` (`runs` / `time_limit` / `tool_limit`).
- **Snapshot library two-track mismatch**: `tools/gen_fixtures.py` wrote snapshots to
  `benchmark/fixtures/snapshots/` while the runtime `SnapshotStore` reads `benchmark/snapshots/`
  (`evaluation.snapshot_dir`), and the generated `index.json` held `pages` as a string list instead
  of `SnapshotPage` objects — so `snapshot verify` crashed outright (`AttributeError`) and
  `--offline-replay` found no snapshots. Now unified on the runtime directory with a field-exact
  `index.json` (`pages[].snapshot_path` relative to the task dir).
- **`validate`'s snapshot-existence check pointed at the wrong path**: used to check `snapshots/`
  under the task dir; now checks the runtime snapshot library
  `benchmark/snapshots/<task_id>/index.json`.
- **`_sources_of` didn't pass `task_id`**: under `--offline-replay` it counted sources from **all**
  tasks in the snapshot dir toward the current task, inflating `source_precision` / `source_level` /
  `citation_coverage`. Now scoped to `task_id`; no replay without task identity (rather the agent's
  own sources than cross-task contamination).
- **`is_sensitive_env` defined but never called**: sensitive vars like `OPENAI_API_KEY` in
  `env_passthrough` produced zero warnings. `build_sandbox_env` now warns via `UserWarning` before
  passing through (explicit declarations still take effect, nothing blocked).
- **No retries in semantic grading**: `invalid_response` (non-JSON response / missing fields) now
  retries up to `grader_model.max_retries` (default 1, design §5.3); network-class errors don't
  retry and go straight to degraded.
- **`query_runs` re-synced everything**: `sync_db` is incremental on `(mtime_ns, size)` —
  unchanged JSONL files are no longer re-read; `write_grade` appends are still picked up.
- **`_run_from_records` took the first `run_end`**: now takes the last, so re-run/appended JSONL
  reads current state, not stale state.
- **`_persist_raw` landing spot implicitly depended on workspace layout**: now explicitly based on
  `config.results_dir`, with `stdout_path` clearly relative to `results/`.
- **Two platform-portability tests**: `/bin/echo` (absent on Windows) now uses the current
  interpreter; path assertions normalize separators.
- **`gen_demo_benchmark.py` defaulted output to `/tmp/...`**: now `tempfile.gettempdir()`,
  cross-platform.
- `grade --run-id` crash (read nonexistent `GradeResult.error_codes`).
- `--suite` raised `TypeError: 'Suite' object is not iterable`.
- Double-nested `params:` parsing in `AgentSpec.from_dict`.
- `json_schema` `array.minLength` not enforced (now counts elements).
- `cmd_report` `tasks[].category/difficulty/network` all `unknown`.
- Duplicate error output for fixture-hash / manifest illegal filenames.
- **False positives in `tools/check_report_html.py` URL scan**: the original scanned the whole
  document for `http(s)://`, misflagging source URLs embedded in report JSON data (e.g.
  `https://yz.chsi.com.cn/tj/`) as external resources — core50 reports failed `26/27`. URL scanning
  now excludes `<script>` data blocks, plus a new "no proactive outbound in scripts"
  assertion (fetch/XHR/WebSocket/EventSource/sendBeacon/new Image) — real external links are still
  caught. Measured `28/28 PASS` on core50 reports (6 new regression tests).
- **`release_check.sh` hardcoded `python3` / `kaoyanbench`**: unusable off-Unix or without
  `pip install -e .`; step 2 also ran pytest twice and swallowed exit codes through a pipe. Now
  supports `PY` / `KYB` env overrides, path-membership checks compare via Python normalization
  (Windows slash-safe), the pytest step captures output in a single run, and step 7 adds HTML
  report acceptance (`check_report_html.py`; 7 steps → 8).
- **pytest default basetemp depended on system `%TEMP%`**: restricted environments (this machine's
  `%TEMP%\pytest-of-<user>` permission denied) died with `PermissionError` at collection
  (117 errors). Now pinned in `pyproject.toml` to `--basetemp=results/.pytest_tmp` (in-repo,
  gitignored); explicit flags still override.
- **Unbounded `--runs`** (QA P3-1): `--runs 999999` launched massive repeats unguarded, hanging for
  minutes in measurement. Now `cmd_run` validates the merged `--runs` / `suite.defaults.runs` /
  `config.evaluation.runs`: `< 1` and `> MAX_RUNS_PER_TASK` (100) both error with exit code 2;
  `--runs 0` is no longer silently treated as 1.
- **Two typos in design §6.4 summary table**: `DET/HYB` written 26/24 (correct **24/26**),
  offline/online written 31/19 (correct **27/23**). The §6.3 per-task table and measured
  `benchmark/tasks/public/**/task.json` both show `DET 24 / HYB 26`, `offline 27 / online 23`.
  Fixed all three spots in `docs/01` plus downstream references in README / `docs/05` / `docs/06` /
  `docs/07`.

### Known Limitations (recorded boundaries, no whitewash)

- **Private set ships 0 tasks**: v1.0 delivers only the Public/Private split **mechanism**
  (`--split`, `benchmark/tasks/private/`) — the private dir holds only a README, **no private
  content**. This is the explicit v1.0 boundary of design R6.
- **Online-task snapshots not captured**: v1.0 has 23 `network=online` tasks and **all 23 web
  snapshots are missing** (T-07 leftover, needs networked capture). So real end-to-end semantic
  grading of online tasks is **uncovered**; CI runs only the offline subset by default. The only
  existing snapshots are **local fixed pseudo-snapshots** for 3 offline tasks (SEARCH-011 /
  SEARCH-012 / RES-002, generated by `tools/gen_fixtures.py`, never networked) for verifying
  `snapshot verify` and `--offline-replay` plumbing.
- **Real-LLM Semantic Grader unverified in CI**: without an API key, semantic grading degrades to
  `grader_mode=degraded` (`degraded_reason=no_api_key`); **degraded results must never be written to
  a regression baseline** (R9).
- **Docker sandbox unimplemented**: `runtime.docker.enabled=true` is a v1.0 P2 placeholder that
  errors explicitly instead of degrading silently; sandbox isolation is explicitly **process-level**,
  not proof against writes outside `/tmp` or network exfiltration.
- **L2 (agent-layer replay proxy) not in v1.0**: only the `KAOYANBENCH_REPLAY_DIR` semantic
  placeholder remains.
- **No task-level Runner retries**: v1.0 retries cover only semantic-grading `invalid_response`
  (the one case design §5.3 mandates). Agent timeouts / spawn failures **don't auto-rerun** — the
  design defines no retry counts or conditions for them, and blind retries would change grading
  semantics (repeat quota consumption, Pass@k caliber effects).
- **CI real trigger pending verification**: directory renamed from `_.github` to `.github`; YAML
  syntax and job structure of all three workflows statically validated; but the **first real
  GitHub Actions trigger** still needs one confirmation after pushing to remote (Actions runtime
  can't run locally; see `docs/07` §I).

### Notes

- All institutions/data inside fixtures are **fictional** and represent no real organization.
- Tasks involving real institutions' current-year figures always have empty ground truth — only
  point hits + source levels + year tags are judged (R3).
- Grader model and model under test are **forcibly separated** (`allow_same_model` defaults
  `false`).
