## 1. Artifact list

`kaoyanbench report --suite <id> --agent <name> --tag <tag>` produces, by default, under
`reports/<suite_id>__<agent>__<tag>/`:

| File | Role | Notes |
|---|---|---|
| `report.json` | **Single source of truth** | Everything else is rendered from it; programmatic consumers read only this |
| `report.md` | Human-readable | Tabulated, paste-ready for GitHub |
| `report.html` | Human-readable | **Single file, zero CDN, zero external requests**; inline CSS/JS + hand-drawn SVG charts |
| `report.csv` | Tabular | One row per task, Excel-friendly (enabled with `-f csv`) |

CSV and HTML never carry information absent from the JSON; `report.json` wins any numeric dispute.

  "tasks":   [ ... ],          // §8

## 5. `summary` section (aggregate metrics)

`null` means **no sample for that metric** (not zero). In cross-tag comparison a `null` turns the gate
into `skipped`, never a pretended pass.

### 5.1 Success and pass rates

| Field | Definition |
|---|---|
| `task_success_rate` | Tasks with `task_success=True` / total tasks |
| `failure_rate` | `1 - task_success_rate` |
| `pass_at_1` | Share of tasks succeeding on the very first run |
| `pass_at_3` | Share of tasks succeeding at least once within 3 runs (meaningful only with `--runs ≥ 3`) |

> `task_success` = total score ≥ `pass_threshold` (default 60) **and** no critical check failed
> **and** zero hallucination violations.

### 5.2 Scores

| Field | Definition |
|---|---|
| `score_mean` / `score_median` / `score_p90` | Mean / median / P90 of per-task total scores |

### 5.3 Quality dimensions

| Field | Definition |
|---|---|
| `factuality_mean` | Factuality (point-hit rate and friends) |
| `source_precision_mean` | Source precision (share of cited sources meeting the required level) |
| `search_recall_mean` | Retrieval recall (share of required sources/points found) |
| `citation_accuracy_mean` | Citation accuracy (whether citations actually support their claims) |
| `hallucination_rate_mean` | Hallucination-violation rate (share of tasks hitting `must_not_claim`) |
| `tool_success_rate_mean` | Tool-call success rate |

### 5.4 Efficiency and cost

| Field | Definition |
|---|---|
| `tool_calls_mean` / `tool_calls_p90` | Tool-call counts |
| `tokens_mean` / `tokens_p90` | Token consumption (present only when `usage_source != none`) |
| `latency_seconds_mean` / `_median` / `_p90` | End-to-end latency (seconds) |
| `cost_usd_mean` / `cost_usd_total` | Cost (needs `pricing` configured, else null) |

### 5.5 Usage trustworthiness

| Field | Definition |
|---|---|
| `usage_missing_count` | Tasks with no usage at all (`usage_source=none`) |
| `usage_estimated_ratio` | Of those, the share estimated from character counts (`estimated=true`) |

> **Never fills in 0**: missing tokens/cost stay `null`, with the gap sized honestly by the two fields above.

## 6. `score_breakdown_mean` section (100-point scale, 7 dimensions)

```jsonc
{ "factuality": 48.95, "source_quality": 15.51, "citation": 0.78,
  "completeness": 17.35, "tool_execution": 5.2, "task_completion": 2.13,
  "efficiency": 4.96, "total": 94.88 }
```

Default weights (tunable in `config/default.yaml` under `evaluation.weights`, overridable per task):

| Dimension | Default weight | Max points |
|---|---|---|
| `factuality` | 0.30 | 30 |
| `source_quality` | 0.20 | 20 |
| `citation` | 0.15 | 15 |
| `completeness` | 0.15 | 15 |
| `tool_execution` | 0.10 | 10 |
| `task_completion` | 0.05 | 5 |
| `efficiency` | 0.05 | 5 |

**Neutral reallocation**: when a task has no checks at all for some dimension, that dimension's weight
is redistributed proportionally (`reallocated`), so a search task is never docked for lacking planning
checks. Hence `total` is not a naive sum of the dimensions.

```jsonc
{ "category": "search", "label": "搜索与信息检索", "task_count": 12,
  "task_success_rate": 1.0, "score_mean": 91.78, "factuality_mean": 1.0,
  "search_recall_mean": 0.78, "source_precision_mean": 1.0,
  "citation_accuracy_mean": null, "hallucination_rate_mean": 0.0,
  "latency_seconds_mean": 0.0, "tool_calls_mean": 0.5,
  "cost_usd_mean": null, "pass_at_1": 1.0, "pass_at_3": 1.0 }
```

(`labels` are Chinese in the artifacts.) `by_difficulty` is isomorphic, keyed by
`difficulty` / `label` (Easy / Medium / Hard / Expert).

## 8. `tasks[]` section (per-task detail)

| Field | Type | Notes |
|---|---|---|
| `task_id` | str | Task ID |
| `category` / `difficulty` / `network` | str | Metadata (`offline` / `online` / `hybrid`) |
| `grader_type` | str | `deterministic` / `semantic` / `hybrid` / `manual` |
| `grader_mode` | str | This task's grading mode: `full` / `degraded` |
| `n_runs` | int | Actual run count |
| `pass_at_1` / `pass_at_3` | bool | This task's pass outcome |
| `score` | float | Total score (100-point scale) |
| `metrics` | obj | Task-level `Metrics` (see below) |
| `usage_source` | str | `agent_reported` / `usage_file` / `estimated_from_chars` / `none` |
| `checks` | list | Per-check verdict detail (see below) |
| `error_codes` | list | Error codes hit by this task (§9 code table) |
| `trace_ref` | str | Full-trace JSONL path (relative to `results/`) |

`metrics` fields: `factuality` / `source_precision` / `search_recall` / `citation_accuracy` /
`hallucination_rate` / `tool_success_rate` / `tool_calls` / `tokens` / `latency_seconds` / `cost_usd`.
`null` means no sample for that task.

Each `checks[]` entry:

```jsonc
{ "id": "c1", "type": "numeric", "dimension": "factuality",
  "passed": true, "critical": false,
  "detail": "$.count = 10，期望 eq 10（tol=0）" }
```

(`detail` strings are Chinese in the artifacts.)

- `critical=true` with `passed=false` → `task_success=False` for that task (single-vote veto);
- `detail` is the human-readable rationale, for manual review.

## 9. `errors[]` section (error-code aggregation)

```jsonc
{ "code": "CITATION_FAILURE", "count": 27, "ratio": 1.0,
  "sample_task_ids": ["HAL-004", "POL-001", "POL-002"] }
```

11 error codes (design §4.10):

`SEARCH_FAILURE` / `SOURCE_SELECTION_FAILURE` / `PARSING_FAILURE` / `TOOL_FAILURE` /
`CITATION_FAILURE` / `HALLUCINATION` / `FORMAT_FAILURE` / `CONSTRAINT_VIOLATION` /
`CALCULATION_FAILURE` / `TIMEOUT` / `UNKNOWN`

`ratio` = hit tasks / total tasks. `sample_task_ids` is only a sample; the full list lives in each
task's `error_codes`.

## 10. `comparison` section (regression chapter)

Non-null only for `report --baseline <tag>` or `regression` / `compare`:

```jsonc
{
  "baseline_tag": "v2.7.0", "current_tag": "v2.8.0",
  "deltas": [ { "metric": "task_success_rate", "label": "任务成功率",
                "baseline": 0.92, "current": 0.88, "delta_pp": -4.0,
                "delta_abs": -0.04, "ratio": 0.96, "direction": "flat|up|down" } ],
  "gates": [ { "name": "task_success_rate", "label": "任务成功率门禁",
               "metric": "task_success_rate", "threshold_text": "...",
               "delta_pp": -4.0, "result": "pass|fail|warn|skipped" } ],
  "newly_failed_tasks": ["SEARCH-004"],
  "newly_passed_tasks": [],
  "verdict": "pass|warn|fail",
  "verdict_label": "通过|告警|失败"
}
```

(`label` / `verdict_label` strings are Chinese in the artifacts.)

Gate rules (`gates` in `config/default.yaml`, Δpp in `absolute` mode):

| Gate | Default threshold | Level |
|---|---|---|
| `task_success_rate` | drop > 5pp | **fail** |
| `citation_accuracy_mean` | drop > 5pp | **fail** |
| `hallucination_rate_mean` | rise > 3pp | **fail** |
| `latency_seconds_p90` | above baseline ×1.5 | warn |

Exit codes: `verdict=fail` → 1; `warn` → 0 (1 with `--strict-warn`); no baseline data → 2.
Metrics without samples yield `skipped` (**counts neither as fail nor as pass**).

## 11. `grader_mode` and trustworthiness (**read this first**)

`grader_mode` tells you how much of a report's score is "semantic grading" vs "rule-based degraded"
scoring:

| Value | Meaning |
|---|---|
| `full` | Every task went through complete grading (deterministic checks + grader model) |
| `degraded` | Every task went through rule-based degraded grading |
| `mixed` | Some tasks `full`, some `degraded` (see `degraded_task_count`) |

**Degradation triggers** (hard-coded, design §5.3):

| Trigger | `degraded_reason` | Behavior |
|---|---|---|
| No `GRADER_API_KEY` | `no_api_key` | Rule-based grading, results still produced |
| Request timeout / connection failure | `network_unreachable` | Same |
| Non-JSON response / missing fields | `invalid_response` | Same, **at most 1 retry** (`grader_model.max_retries`) |

Degraded scoring formula (`fallback_semantic_score`):

```
score = 0.5 × point-keyword hit rate + 0.3 × required_fields coverage + 0.2 × length/structure soundness
```

**Must-knows when reading a report**:

1. `degraded` task scores correlate weakly with "semantic quality" — they reflect keyword/field
   coverage only;
2. Means in `summary` mix `full` and `degraded` scores — when the two sides' `degraded_task_count`
   differs a lot, cross-version conclusions are not directly trustworthy;
3. **Degraded results must never be written to a regression baseline** (design R9) — `nightly.yml`
   enforces this; the versioned baseline lives in `benchmark/baselines/`;
4. The HTML report shows a red warning banner on `degraded`/`mixed` — **never silently pretending
   to have graded**.

## 12. `schema_version` and compatibility

- Currently `"1.0"`. Field **additions** don't bump it; **renames/removals/semantic changes** bump to
  `1.1` / `2.0`.
- Consumers should: depend only on fields documented here; ignore unknown fields; treat `null`
  everywhere as "no sample", never as 0.
- `report.json` is the single source of truth; `report.md` / `report.html` / `report.csv` are
  derived views.
