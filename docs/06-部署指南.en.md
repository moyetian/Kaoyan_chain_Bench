## 4. ★ Install-misdirection detection and repair (the focus of this deployment)

**Background**: on this machine `pip install -e .` once pointed at an upstream verification copy at
`/tmp/kybcheck`; it must point at `/workspace/KaoyanBench`. An editable install writes the project
path into `.pth` / `__editable__` files inside site-packages — install from the wrong directory and
the `kaoyanbench` command loads **a different copy's source**, producing spooky "edits don't take
effect" / "version-behavior mismatch" symptoms.

### 4.1 Detection

```bash
# ① Where is the module actually loaded from (most direct)
python3 -c "import kaoyanbench; print(kaoyanbench.__file__)"
#   correct: /workspace/KaoyanBench/src/kaoyanbench/__init__.py
#   wrong:   /tmp/kybcheck/src/kaoyanbench/__init__.py  <- misdirected install

# ② What editable location does pip record
python3 -m pip show kaoyanbench | grep -i "location\|editable"
#   expect: Editable project location: /workspace/KaoyanBench

# ③ Which executables do the commands resolve to
which -a kaoyanbench kyb

# ④ Cross-check: version + project root
kaoyanbench --version
python3 -c "from kaoyanbench.core.config import find_project_root; print(find_project_root())"
```

### 4.2 Repair

```bash
# Uninstall the misdirected copy first
pip uninstall -y kaoyanbench

# Reinstall from the correct directory
cd /workspace/KaoyanBench
pip install -e .

# Verify again
python3 -c "import kaoyanbench; print(kaoyanbench.__file__)"
# expect: /workspace/KaoyanBench/src/kaoyanbench/__init__.py
```

> If `pip show` still reports `/tmp/kybcheck`, look for leftover `.pth`/`__editable__*.pth` files
> pointing at the old path, or a venv/pyenv interpreter mismatch — use `python3 -m pip ...`
> (never bare `pip`) so you install into the same interpreter.

## 5. Build fixtures (deterministic, offline)

Smoke's 6 tasks are fixture-driven. Fixtures are **deterministically** generated by
`tools/gen_fixtures.py` (two consecutive runs give identical aggregate sha256).

```bash
cd /workspace/KaoyanBench
kaoyanbench fixtures build             # invokes tools/gen_fixtures.py
# Verify existing fixtures (manifest files exist and sha256 matches)
kaoyanbench fixtures check             # expect: fixtures verified ✅
```

> Without `fpdf2` / `openpyxl` the fixture generator falls back to a built-in minimal PDF generator
> and degrades Excel to CSV with a warning (T-01 design) — **it does not fail**. For byte-identical
> PDF/XLSX fixtures, `pip install -e ".[fixtures]"` is recommended.

## 6. Validate the task suites (required in CI)

```bash
kaoyanbench validate --suite core50
# expect: suite=core50  tasks=50  error=0  warn=28
#         trailing: validate passed ✅
echo "exit=$?"                        # expect 0
```

Exit-code convention (design §5.10, Chinese-only): `0` pass / `2` has errors / `1` (warns fail only
with `--strict`).

## 8. Full core50 (nightly / release gate, **never in PR gates**)

> R5: research tasks cap at 900s each; 50 tasks × 3 runs serially caps at 12.5h in theory.
> **Full core50 runs only as nightly / release gates.**

```bash

kaoyanbench run --suite core50 --agent mock --tag core-mock --concurrency 4
kaoyanbench report --suite core50 --agent mock --tag core-mock -f json,markdown,html,csv
```

With a real agent (example: kaoyan_chain):

```bash

```

## 9. Regression gate

```bash
# Both tags must have been run already (same suite / same agent)
kaoyanbench regression --baseline v2.7.0 --current v2.8.0 --suite core50
```

Exit codes: `0` pass / `1` gate fail (CI must mark failed) / `2` runtime error.

Gate thresholds (`config/default.yaml: gates`, design §33):

| Metric | Threshold | Level |
|---|---|---|
| `task_success_rate` | drop > 5pp | fail |
| `citation_accuracy_mean` | drop > 5pp | fail |
| `hallucination_rate_mean` | rise > 3pp | fail |
| `latency_seconds_p90` | above baseline ×1.5 | warn |

Since the review fix, the `smoke` mock baseline is versioned in `benchmark/baselines/` (CI
read-only; a missing baseline fails the gate — self-comparison is forbidden). See
`benchmark/baselines/README.md` for the update flow.

## 11. Docker usage

The project has **zero runtime dependencies**, so images should stay lean. The repo ships a
`Dockerfile` (based on `python:3.11-slim`):

```bash
# Build
docker build -t kaoyanbench:1.0.0 .

# Validate suites (offline)
docker run --rm kaoyanbench:1.0.0 kaoyanbench validate --suite core50

# Smoke run (offline)
docker run --rm kaoyanbench:1.0.0 kaoyanbench run --suite smoke --agent mock --tag docker-smoke

# Mount host results / reports to keep artifacts
docker run --rm -v "$PWD/results:/app/results" -v "$PWD/reports:/app/reports" \
  kaoyanbench:1.0.0 kaoyanbench run --suite smoke --agent mock --tag docker-smoke

# For semantic grading, pass secrets as env vars (never bake them into the image)
docker run --rm -e GRADER_BASE_URL -e GRADER_API_KEY kaoyanbench:1.0.0 \
  kaoyanbench validate --suite core50
```

### Sandbox isolation level (stated as-is, design R10)

- **v1.0 isolation is "process-level"** — not container-level, let alone kernel-level.
- Concrete measures (`core/sandbox.py`): isolated workspace; env allowlist (**no `*_API_KEY` passed
  to children** when `env_passthrough=[]`); `HOME/TMPDIR/XDG_CACHE_HOME` redirected into the
  workspace; timeout SIGTERM → grace → SIGKILL.
- **Cannot stop**: child writes outside `/tmp`, network exfiltration.
- `runtime.docker.enabled=true` is **unimplemented** in v1.0 (P2 placeholder); setting it raises an
  explicit `DockerNotAvailableError` instead of silently degrading. The Dockerfile here is a
  deployment vehicle for packing the CLI into a container — **not** the Sandbox's Docker-isolation
  feature.

## 12. Troubleshooting

### 12.1 Misdirected install (edits don't take effect / version mismatch)
See §4. Core command: `python3 -c "import kaoyanbench; print(kaoyanbench.__file__)"`.

### 12.2 Degraded due to missing api_key
- Symptom: red degraded banner on top of the report; `grader_mode=degraded`;
  `degraded_reason=no_api_key` (or `network_unreachable` / `invalid_response`).
- Cause: `GRADER_BASE_URL` / `GRADER_API_KEY` unset or empty.
- Fix: ① need real semantic grading → set both; ② offline deterministic grading only → ignorable
  (deterministic checks still work).
- **★ R9: `grader_mode=degraded` results must never be written to a regression baseline** —
  polluting the baseline is now blocked in CI.

### 12.3 Online-task failures / `needs_snapshot`
- Symptom: `validate` warns `requires_snapshot` on the 23 online tasks (warn, not error); runs
  report missing snapshots.
- Cause: in v1.0 the 23 snapshots were not yet captured (T-07 leftover, needs network); v1.0
  shipped only the snapshot mechanism plus L1 replay. Since v1.1 the 23 tasks ship **synthetic
  mirror** snapshots (fictional replay corpora for `--offline-replay` link verification); real web
  snapshots still await `snapshot fetch` capture and versioning.
- Snapshot library: `benchmark/snapshots/<TASK_ID>/` (i.e. `evaluation.snapshot_dir`).
  `tools/gen_fixtures.py` generates **local fixed pseudo-snapshots** for SEARCH-011 / SEARCH-012 /
  RES-002 (never touches the network), so these three pass `kaoyanbench snapshot verify --task all`
  directly and support `--offline-replay` L1 replay.
- Fix: ① offline scenarios run only the offline subset (smoke / deterministic tasks);
  ② capturing needs network: `kaoyanbench snapshot fetch --task SEARCH-004 --url <URL>`, then
  `kaoyanbench snapshot verify`; ③ use `--offline-replay` for local-snapshot replay (issues zero
  network requests).
- **Don't pretend coverage**: real end-to-end semantic grading of online tasks is **uncovered**
  without network/snapshots.

### 12.4 Timeouts (long research tasks)
- Symptom: `timed_out=true`, `exit_code=-15`, `errors=[PARSING_FAILURE, TIMEOUT]`; the task counts
  as FAIL but is **never lost**.
- Fix: `--time-limit N` overrides the per-task cap; or lower `--concurrency` (default 1) to avoid
  resource contention; full core50 runs only in nightly.

### 12.5 Non-zero `validate` exit codes
- `2`: error-level issues exist (schema / fixture-hash mismatch / ground-truth violation) — must fix.
- `1`: only with `--strict`, warns also fail (warns don't block by default).

### 12.6 SQLite
`results/benchmark.db` is a **derivative — `rm` and rebuild any time** (`store.rebuild_db()`). If the
database corrupts: `rm results/benchmark.db`, and the next query auto-`sync_db`s a rebuild from JSONL.

## 13. Pre-release check in one command

```bash
bash tools/release_check.sh
```

8 steps: install & version → pytest → `validate` → `fixtures` → offline smoke → report generation &
artifact check → HTML report acceptance → regression gate; any failure exits non-zero.

On non-Unix environments (e.g. Windows Git Bash) or without `pip install -e .`, override the
interpreter and CLI entry via env vars:

```bash
PY=py KYB="py -m kaoyanbench" PYTHONPATH=src bash tools/release_check.sh
```

See `docs/07-上线检查清单.md` (Chinese-only) and `docs/08-回滚预案.md` (Chinese-only).
