## 1. 目标与边界

### 1.1 目标（一句话）

为 `kaoyan_chain` 建立一套**可重复执行、可自动评分、可持续回归**的考研场景 Agent 评测基准，使其既能与 Claude Code / Codex / OpenCode / WorkBuddy 等通用 Agent 横向比较，又能在自身每次版本迭代时给出可判定的回归结论。

### 1.2 v1.0 交付目标（对应《原方案》第 1 节 10 条，做取舍映射）

| 《原方案》目标 | v1.0 是否覆盖 | 落地方式 |
|---|---|---|
| 1. 通用 Agent 基础能力 | 部分 | 仅留 `GeneralBench` 目录与 adapter 抽象占位，不放任务 |
| 2. 考研领域信息检索 | 是 | search 12 题 |
| 3. 院校/招生/政策高时效信息 | 是 | university 9 + policy 5 |
| 4. 网页/PDF 等异构资料处理 | 是 | pdf 5 + exam 5 |
| 5. 多步骤工作流 | 是 | research 4 |
| 6. 引用/证据/抗幻觉 | 是 | hallucination 5 + 全任务 Citation Accuracy |
| 7. 长任务稳定性 | 部分 | research 的 expert 题（time_limit 900s+，tool_limit 100） |
| 8. 成本/时间/Token/效率 | 是 | 全任务采集，带 `usage_source` 溯源 |
| 9. 自动评分与版本回归 | 是 | Grader + Scorer + Regression Gate + CI |
| 10. 公开可复现基准 | 是（机制） | Public/Private 分离 + 快照 + 固定 seed + `results/` 全量留痕 |

### 1.3 v1.0 明确包含（In Scope）

1. 独立可发布 Python 项目 `KaoyanBench`（MIT，git 已初始化，含 LICENSE / README / pyproject.toml / .gitignore）。
2. 任务集：`core50`（Public 50 题，8 类）+ `smoke`（6 题离线冒烟集，CI 用）+ `private_demo`（Private 机制验证集）。
3. 任务注册表：目录扫描 → `List[Task]`，带 schema 校验与 `kaoyanbench validate`。
4. 插件式 Runner：`command` / `http` / `mock` / `echo` 四种内置，注册表式扩展。
5. 运行环境隔离：进程级 sandbox（独立 workspace + 环境变量白名单 + 超时 SIGTERM/SIGKILL）；Docker 仅保留配置位与脚本模板。
6. 日志：每次运行输出完整 trace（JSONL，含 tool_arguments / tool_results / errors / usage）。
7. Grader：Deterministic（声明式 checks）、Semantic（OpenAI 兼容端点，可降级）、Hybrid、Manual（导出占位）。
8. Scorer：100 分制 7 维评分 + 11 项关键指标（`Metrics`）。
9. Reporter：`report.json`（唯一事实源）+ `report.md` + `report.html`（单文件、零 CDN、手写 SVG 图表）。
10. Regression：`compare` + `regression` 门禁判定 + 非零退出码供 CI 消费。
11. CLI：`list / run / grade / report / compare / regression / snapshot / fixtures / validate`。
12. Snapshot：抓取、保存（URL/title/timestamp/sha256/snapshot）、校验、`--offline-replay`（L1 评分层）。
13. Fixtures：确定性生成脚本（PDF/HTML/CSV/Excel/Markdown），虚构院校，绝不编造真实院校数字。
14. 存储：JSONL（原始）+ SQLite（聚合查询）+ 文件树（任务与报告）。
15. Public / Private 分离机制（`--split` 参数 + 目录隔离 + 单测覆盖）。

### 1.4 v1.0 明确不包含（Out of Scope，写死以免扯皮）

| 不包含项 | 说明 / 占位方式 |
|---|---|
| Leaderboard 网站 / 服务端 / 在线数据库 | 不做。报告是本地静态产物。 |
| SWE-bench / Terminal-Bench / BrowserGym 全量接入 | 不做。仅 `tools/import_external.py` 留 adapter 抽象与 `GeneralBench` 空目录（Phase 3 接口占位）。 |

| Human Grader 的评分 UI | 不做界面。仅导出 `reports/<id>/human_review.jsonl` 供人工填 `score` 字段后可回灌。 |
| 真实浏览器自动化（Playwright / Selenium） | 不做。 |
| 分布式 / 云端调度 | 不做。v1.0 为本地串行 + 可选进程级并发（`--concurrency`，上限 4）。 |
| 通用爬虫引擎 / 搜索引擎自建 | 不做。仅提供最小 `snapshot fetch`（单 URL 抓取落地）。 |
| Private 100 题全量 | 不做。v1.0 只交付机制 + 0 条内置 private 任务（可选 P2 附 5 条样例）。 |
| 100 题 Public 全量 | 不做。v1.0 = 50 题。第 4 节的 100 题配置作为 Phase 2 目标写进 `docs/05-roadmap.md`。 |
| 自动 Prompt 优化 / 改进建议生成 | 不做。 |
| 多语言（英文）报告 | 不做，v1.0 中文报告；字段名为英文（便于国际化后续扩展）。 |
| 模型微调、评测模型训练 | 不做。 |

## 2. 功能清单（按模块 × 优先级）

优先级定义：**P0** = v1.0 必须交付；**P1** = v1.0 内尽量交付，缺失不阻塞主线；**P2** = 明确可延后，只留接口/占位。

### 2.1 Task Registry（任务注册表）

| 功能 | 优先级 | 说明 |
|---|---|---|
| 目录扫描加载任务（public/private × 8 类） | P0 | `load_task_dir` / `load_suite` |
| task.json schema 校验与错误定位 | P0 | 缺字段/类型错/权重和不为 1 → `TaskValidationError`，带文件路径 |
| suite manifest（yaml）加载与过滤 | P0 | `core50` / `smoke` / `private_demo` |
| 过滤：split / category / difficulty / tag / task_id | P0 | `list` 命令复用 |
| fixture 完整性校验（references/ 文件存在且 hash 匹配） | P0 | `validate` 命令，CI 必跑 |
| 快照存在性校验（联网题若无快照则标记 `needs_snapshot`） | P1 | 不阻塞，仅告警 |
| 任务级 `grader.py` 逃生舱（importlib 动态加载） | P2 | 声明式 checks 为主，代码逃生舱延后 |

### 2.2 Runner（Agent 适配层）

| 功能 | 优先级 | 说明 |
|---|---|---|
| `AgentRunner` Protocol + 注册表 `get_runner()` | P0 | 统一 `run(task, ctx) -> AgentOutput` |
| `EchoRunner` | P0 | 回显指令，用于 pipeline 烟囱测试 |
| `MockRunner` | P0 | 按 `config/agents/mock.yaml` 输出预设答案/工具序列，**离线跑通全链路** |
| `CommandRunner` | P0 | 调用外部 CLI（`ky` / `claude -p` / `codex exec` / `opencode run`），支持 argv 模板、stdin、cwd、env、超时 |
| `HttpRunner` | P1 | OpenAI 兼容端点，用于无 CLI 的 harness |
| stdout/stdout 解析适配（json / jsonl / text 三级回退） | P0 | `parse.format` + `parse.fallbacks` |
| token/cost 采集钩子（3 级回退 + `usage_source`） | P0 | 见第 4.7 节 |
| tool_calls 采集（来自 Agent 上报 / 命令 stdout / 无法采集则 `null` 并标注） | P0 | 不允许伪造 |
| 重试与失败分类（TIMEOUT / TOOL_FAILURE / UNKNOWN） | P0 | 第 4.10 节错误分类 |
| 并发运行（`--concurrency`） | P1 | 默认 1 |

### 2.3 Sandbox（运行隔离）

| 功能 | 优先级 | 说明 |
|---|---|---|
| 每 run 独立 workspace 目录 | P0 | `results/workspaces/<run_id>/` |
| references 复制到 workspace，Agent 只可见自己那份 | P0 | 防串扰 |
| 环境变量白名单注入（`PATH/HOME/LANG/TMPDIR` + 配置声明的 env） | P0 | 默认**不**透传 `*_API_KEY`，除 `env_passthrough` 显式声明 |
| `HOME/TMPDIR/XDG_CACHE_HOME` 重定向到 workspace | P0 | 防缓存污染 |
| 超时控制（SIGTERM → 5s → SIGKILL） | P0 | `time_limit` + `timeout_grace_sec` |
| 工作区保留/清理（`--keep-workspace`） | P1 | 默认清理成功 run，保留失败 run |
| Docker 运行模式 | P2 | 仅 `runtime.docker.*` 配置位 + `scripts/docker_run.sh` 模板，默认关闭 |

### 2.4 Logger（日志与留痕）

| 功能 | 优先级 | 说明 |
|---|---|---|
| Run 级 JSONL 流式写入（边跑边写，崩溃不丢） | P0 | `results/runs/<run_id>.jsonl` |
| ToolCall 级事件落盘 | P0 | 含 arguments / result / sha256 / 耗时 / 错误 |
| 结果截断与 hash（超长 result 截断 4000 字符并留 sha256） | P0 | 防日志爆炸 |
| `run --runs 3` 的多次运行合并为同一 suite_result | P0 | 计算 Pass@1 / Pass@3 |
| 结构化事件类型（`run_start/tool_call/run_end/error`） | P1 | 便于后续可视化时间线 |
| 敏感信息脱敏（api_key 等） | P1 | 正则替换为 `***` |

### 2.5 Grader（评分）

| 功能 | 优先级 | 说明 |
|---|---|---|
| 声明式 check 引擎（16 种检查类型） | P0 | 第 5.3 节 |
| `DeterministicGrader` | P0 | 纯标准库 |
| `SemanticGrader`（OpenAI 兼容端点） | P0 | 固定 model/temperature/prompt_version |
| 降级路径：无 key / 无网络 / 响应非法 → 规则化评分 + `grader_mode="degraded"` | P0 | **不允许静默假装评过** |
| `HybridGrader`（deterministic 结果 + semantic 结果按权重合并） | P0 | 主力 grader |
| `ManualGrader`（导出 human_review.jsonl） | P1 | 不计入自动分 |
| 证据等级判定（E0~E5，按域名/路径/年份规则） | P0 | `config/graders/source_levels.yaml` |
| Citation Accuracy 判定（引用是否支持其断言） | P0 | deterministic 用检索匹配 + semantic 用评测模型 |
| `must_not_claim` 违规检测（幻觉） | P0 | 命中即 `hallucination` 计 1，且 task_success=False |
| 年份/时效判定（`year_tag` 检查） | P1 | 政策题关键 |

### 2.6 Scorer（打分与聚合）

| 功能 | 优先级 | 说明 |
|---|---|---|
| 100 分制 7 维打分 | P0 | Factuality30 / SourceQuality20 / Citation15 / Completeness15 / ToolExecution10 / TaskCompletion5 / Efficiency5 |
| 维度中性重分配（无检查项的维度权重按比例转出） | P0 | 第 5.4 节 |
| 11 项关键指标计算 | P0 | 第 4.8 节 `Metrics` |
| `task_success` 判定（分数阈值 + critical check + 0 幻觉违规） | P0 | 阈值默认 60.0，任务可覆盖 |
| 统计聚合 Mean/Median/P90/Success Rate/Failure Rate | P0 | 纯标准库 `statistics` |
| Pass@1 / Pass@3 | P0 | `--runs N` |
| 按 category / difficulty 分组聚合 | P0 | 报告用 |

## 3. 技术选型与目录结构

### 3.1 选型表

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python **≥3.10**（开发/验证环境 3.11.1） | 与 `kaoyan_chain` 一致；`match` 语句、`X \| Y` 类型语法可用 |
| 核心依赖 | **零第三方**（仅标准库） | 主理人前提 5；保证 CI 与离线环境可执行 |
| 配置 | YAML（pyyaml 可选 + 内置受限子集解析器回退） | 《原方案》第 41 节要求 YAML；回退解析器保证零依赖 |
| 结构化存储 | **SQLite（`sqlite3` 标准库）** | 跨版本聚合查询（P90、分组、回归比对）用 SQL 最省事；标准库自带；单文件便于随仓库归档 |
| 原始留痕 | **JSONL**（append-only） | 流式写入、崩溃安全、可 `git diff`、便于逐条 trace 回放 |
| 任务定义 | **文件树 + JSON** | 可 code review、可 PR 评审、可放二进制 fixture（《原方案》第 24/25 节） |
| 报告 | JSON（事实源）+ Markdown + 单文件 HTML | 三种格式《原方案》第 34 节要求；HTML 单文件保证离线双击可开 |
| HTML 图表 | **手写 SVG**（无 CDN、无 JS 图表库） | 零依赖、离线可打开、不引入供应链风险 |
| 模板渲染 | `string.Template` 或纯 f-string 拼装 | 不引 jinja2；jinja2 仅列为可选增强 |
| CLI | `argparse`（标准库） | 零依赖；`kaoyanbench` + 别名 `kyb` |
| 并发 | `concurrent.futures.ThreadPoolExecutor`（P1） | Runner 多为子进程 IO，线程池足够 |
| HTTP | `urllib.request`（标准库） | 快照抓取与 Semantic Grader 调用 |
| 测试 | `unittest`（标准库） | 零依赖；`python -m unittest discover` |
| 可选依赖 | `fpdf2`（PDF fixture）、`openpyxl`（Excel fixture）、`pyyaml`（完整 YAML） | 仅在 `tools/` 与可选路径使用，缺失时给出**清晰报错 + 替代方案**，不在核心路径 |
| 打包 | `pyproject.toml`（setuptools 后端） | 与 `kaoyan_chain` 一致，便于 `pip install -e .` |
| 协议 | MIT | 与 `kaoyan_chain` 一致 |

### 3.2 为什么是「JSONL + SQLite + 文件树」三件套

| 需求 | JSONL | SQLite | 文件树 |
|---|---|---|---|
| 崩溃安全 / 流式写入 | ✅ 强 | ❌ | ✅ |
| 跨版本聚合（P90、分组、Δ） | ❌ 需全量扫 | ✅ 强 | ❌ |
| 人工 review / git diff | ✅ | ❌ 二进制 | ✅ 强 |
| 放二进制 fixture（PDF/HTML） | ❌ | ❌ | ✅ 唯一解 |
| 回归比对（两版本对齐） | 一般 | ✅ | ❌ |

结论：**任务定义用文件树（人写、人审），运行留痕用 JSONL（机器写、流式），查询比对用 SQLite（机器读、聚合），报告产物用 JSON/MD/HTML（人看）**。SQLite 由 JSONL 幂等导入（`store.sync()`，`run_id` 为主键 upsert），**永远是派生数据，可随时重建**——这条定死，避免双写不一致。

## 4. 数据模型

统一约定：

- 所有时间字段为 **ISO 8601 带时区字符串**（例：`2026-09-23T10:00:00+08:00`）。
- 所有比率字段为 **0.0~1.0 的浮点**，报告层再转百分比。**禁止混用 0~100 与 0~1**。
- 所有金额单位为 **USD**，字段后缀 `_usd`。
- 所有耗时单位：字段名显式带单位（`latency_seconds`、`duration_ms`）。
- 所有"未知/采集不到"的值一律为 `null`，**并配一个 `*_source` 字段说明原因**。禁止用 0 冒充。
- 全部 dataclass 定义在 `src/kaoyanbench/core/models.py`，配套 `to_dict()` / `from_dict()`。

### 4.2 Expected / GraderSpec / Check（Ground Truth）

#### 4.2.1 Expected

| 字段 | 类型 | 说明 |
|---|---|---|
| `must_find` | list[Point] | 必须命中的要点（联网题的核心） |

#### 4.2.2 Point / SourceRequirement

```jsonc

{ "id": "p1",
  "weight": 1.0,
  "any_of": ["初试科目", "考试科目"],           // 任一命中即算命中

  "domain_suffix": [".edu.cn", "chsi.com.cn"],

  "dimension": "source_quality",
  "critical": false }
```

**采集优先级（3 级回退，定死）**：

1. `agent_reported`：Runner 从 Agent 输出（stdout JSON 的 `usage` 段 / HTTP 响应的 `usage`）直接读到 → 最准。
2. `usage_file`：Agent 按约定写 `KAOYANBENCH_USAGE_FILE` 指向的 JSON 文件 → 次准。
3. `estimated_from_chars`：command 型只能拿到 stdout 时，`total_tokens ≈ utf8_len(stdout+final_answer)/4`，**必须 `estimated=true`**。
4. `none`：三者都拿不到 → `tokens=null, cost=null`，报告中 `usage_missing_count` +1。**绝不填 0**。

### 5.2 Runner 协议（`core/runner.py`）

@dataclass

    seed: int | None
    task_dir: Path                   # 只读：任务定义目录
    workspace_dir: Path              # 可写：Agent 独占工作区（references 已复制进去）

**维度归属与维度分计算**（`core/scorer.py`）：

```python
def score_from_checks(checks: list[CheckResult],
                      weights: dict[str, float],
                      total: int = 100) -> ScoreBreakdown:
    """
    对每个维度 d：hit_ratio_d = Σ(passed==True 的 weight) / Σ(passed != None 的 weight)
      - 该维度无任何可判定 check（分母 0）→ 视为 neutral：
        其权重按比例重分配给其余有检查的维度，ScoreBreakdown.reallocated = True，
        并在 breakdown.neutral_dimensions 中列出。
      - 全部维度均 neutral（异常）→ 抛 ScoringError，不允许产出 100 分的假分数。
    ToolExecution 维度不由 check 驱动：= 10 * tool_success_rate（null 时 neutral）。
    Efficiency 维度：见下。
    Efficiency = 5 * clamp01(1 - (0.5*tool_calls/tool_limit + 0.5*latency/time_limit))
      且 task_success == False 时 Efficiency 强制为 0；timed_out 时强制为 0。
      tool_calls/tool_limit 或 latency/time_limit 任一不可用 → neutral。
    """
```

def build_semantic_client(cfg: GraderModelConfig) -> SemanticClient | None:
    """cfg.api_key_env 指向的环境变量为空 → 返回 None（触发降级）
    返回 None 时不抛异常，由调用方设置 grader_mode='degraded' + degraded_reason='no_api_key'"""

**降级规则（P0，写死）**：

| 触发 | `grader_mode` | `degraded_reason` | 行为 |
|---|---|---|---|
| 无 api_key | `degraded` | `no_api_key` | 规则化评分（见下），结果照常产出 |
| 请求超时/连接失败 | `degraded` | `network_unreachable` | 同上 |
| 响应非 JSON / 缺字段 | `degraded` | `invalid_response` | 同上，最多重试 1 次 |
| 评测模型 == 被测模型 | **运行前报错** | — | 配置校验阶段抛 `ConfigError`（除非 `allow_same_model: true`，仅 mock/echo 允许） |

规则化降级评分（deterministic fallback for semantic criteria）：
```
score = 0.5*(要点关键词命中率) + 0.3*(required_fields 覆盖率) + 0.2*(长度/结构合理性: 0/0.5/1)
```

### 5.5 Regression 协议（`core/regression.py`）

```python
def compare(baseline: SuiteResult, current: SuiteResult) -> list[MetricDelta]:
    """按 task_id 内连接对齐；仅一侧存在的任务记入 *_missing_* 且不参与 delta。
    delta_pp = (current - baseline) * 100   # 比率指标的「百分点」
    delta_ratio = current / baseline        # 非比率指标（latency/tokens/cost）
    """

def evaluate_gate(deltas: list[MetricDelta], gates: GateConfig) -> list[GateResult]:
    """默认 GateConfig:
       - task_success_rate:      delta_pp < -5.0            → fail
       - citation_accuracy_mean: delta_pp < -5.0            → fail
       - hallucination_rate_mean:delta_pp > +3.0            → fail
       - latency_seconds_p90:    ratio > 1.5                → warn（不 fail）
       指标缺失（null）→ GateResult.result = 'skipped'，并在报告中列出。
    """

def build_regression_report(baseline, current, gates) -> RegressionReport:
    """verdict: 任一 fail → 'fail'；无 fail 但有 warn/skipped → 'warn'；否则 'pass'
       exit_code: pass→0, warn→0（可用 --strict-warn 改 1）, fail→1, 运行错误→2"""
```

★ **单位口径写死**：所有"下降 >5%"指**绝对百分点（pp）**，不是相对百分比。理由：比率型指标的相对变化在基线很低时会失真（0.02→0.03 相对 +50% 但绝对仅 +1pp）。配置项 `gates.mode: absolute|relative`（默认 `absolute`）。

### 6.5 Ground Truth 编写硬规则（任务集工程师必读）

1. **真实院校 + 当年具体数字 → `ground_truth` 必须为 `null`**，只能写 `must_find` 要点 + `required_sources`（E4/E5）+ 年份要求 + `must_not_claim`。
2. **fixture 内所有院校、专业、人名、链接必须为虚构**（北原大学 / 东岭工业大学 / `northplain.edu.example`），文件头写明"虚构数据，仅用于基准测试"。
3. 数字类 ground truth **只允许**出现在 `network=offline` 且有 fixture 的任务（exam / pdf / planning / UNI-008 / UNI-009 / HAL-* / SEARCH-011/012）。
4. 每个任务目录必须有 `README.md`，写明：考点、陷阱、为什么这样设 ground truth、更新时的注意事项。
5. 所有 fixture 必须**由 `tools/gen_fixtures.py` 确定性生成**（固定 seed，无时间戳、无随机数、无字典序遍历依赖），`references/manifest.json` 记录 sha256；`kaoyanbench validate` 会校验 hash。

## 8. 风险与取舍

| # | 风险 | 影响 | 概率 | 应对（已落入设计） |
|---|---|---|---|---|
| R1 | **网页时效性**：联网题的官方页面会变更/下线，导致同一任务在不同日期结论不同，回归失去可比性 | 高 | 高 | ① 快照机制（URL/title/timestamp/sha256/snapshot）；② `--offline-replay` L1 评分层回放；③ 每个 Run 记 `evaluated_at` 与 `sources[].fetched_at`；④ 报告中联网题单独标注 `network=online`；⑤ CI 默认只跑离线子集。**残余风险**：L2 Agent 层回放代理降为 P2，联网题的"Agent 实际看到什么"仍不可完全复现 |
| R2 | **评测模型偏差**：Semantic Grader 自身有偏好（位置偏差、冗长偏好、自我偏好），可能污染分数 | 高 | 中 | ① 评测模型与被测模型强制分离（`allow_same_model` 默认 false）；② temperature=0 + 固定 `prompt_version` + 固定 criteria；③ `GradeResult` 记录 `judge_model` 与 `grader_versions`；④ 语义分只占 `HYB` 的一部分，确定性检查为主；⑤ 后续可做"交换评测模型"敏感性分析（Phase 2） |
| R3 | **真实院校数据不可编造**：若为了凑 ground truth 写死真实院校招生数字，会产出错误基准并误导用户 | 高 | 中 | ① 硬规则：`network=online` 且涉及真实院校当年数字 → `ground_truth=null`；② `validate` 自动拦截；③ fixture 全部虚构院校；④ 数字类 gt 只允许出现在带 fixture 的离线题。**取舍**：这会让联网题的"事实性"只能测"要点命中 + 来源等级 + 年份标识"，不能测精确数字——这是**主动接受的精度损失**，用 exam/pdf/planning 的 100% 确定性题补足区分度 |
| R4 | **成本/Token 统计口径不统一**：command 型 Agent 大多不上报 usage，不同 Agent 口径不同会导致成本对比失真 | 中 | 高 | ① 3 级采集回退 + `usage_source` 字段强制标注来源；② `estimated=true` 的值在报告里打角标；③ `summary.usage_estimated_ratio` / `usage_missing_count` 暴露；④ **跨 Agent 的成本对比在 v1.0 仅作参考，不作为 Gate 项**（Phase 2 再统一口径）。**取舍**：宁可留 null，也不填 0 或瞎估 |
| R5 | **并发与超时**：research 类长任务 900s 超时，串行跑 50 题 × 3 次可能超过 CI 时限；并发又会引入资源竞争与环境变量串扰 | 中 | 中 | ① 默认 `--concurrency 1`；② 每 run 独立 workspace + env 白名单（即便并发也隔离）；③ `smoke` 集 6 题供 CI；④ 超时预算：串行 50 题 × 900s 上限 = 12.5h，**因此完整 core50 不作为 PR 门禁，只作为 nightly/发版门禁**（CI 只跑 smoke + regression 比对已有结果） |
| R6 | **任务集被针对性过拟合**：公开 50 题后，Agent 可能针对固定题目优化 | 中 | 中 | ① Public/Private 分离机制（DoD#15）；② 任务 `version` 字段，gt 变更必须升版；③ Phase 2 扩到 100+100。**取舍**：v1.0 只交付机制，private 内置 0 题——这是明确的 v1.0 边界 |
| R7 | **零依赖约束下的 PDF 生成/解析**：无 `fpdf2`/`pypdf` 时如何造和读 PDF | 中 | 中 | ① 内置最小 PDF 生成器（纯标准库 `zlib`）；② 内置最小文本提取器（解 FlateDecode 流 + 解析 `Tj/TJ` 操作符），**只保证我们自己生成的 PDF 能读**；③ 任务 README 声明 fixture 由本项目生成。**取舍**：不追求通用 PDF 解析能力，只保证基准内部闭环可复现 |
| R8 | **降分不等于变好/变坏**：Task Success 上升但 Latency +45%、Cost +70%（《原方案》第 32 节） | 低 | 高 | ① Gate 之外单列 `latency_p90` WARN 规则；② 报告同时呈现 Accuracy/Reliability/Efficiency 三栏，不做单一总冠军排名（落实第 35 节） |
| R9 | **Semantic Grader 无 key 时结果可信度下降** | 中 | 高 | ① 强制 `grader_mode=degraded` 标注 + 报告红条 + `degraded_task_count`；② 禁止静默通过；③ CI 中若 `grader_mode=degraded` 则**不写入 baseline**（防止污染回归基线） |
| R10 | **沙箱隔离强度不足**：进程级隔离无法防住写 `/tmp` 之外的路径、无法防网络外泄 | 低 | 中 | ① HOME/TMPDIR/XDG 重定向；② env 白名单；③ Docker 配置位与脚本模板（P2）在需要时开启；④ v1.0 明确声明隔离级别为"进程级"，README 不夸大 |

### 8.1 主要取舍汇总（一句话版）

1. 要"8 类覆盖" → 放弃原 MVP 的 20/10/5/5/5/5 配比，Search 与 University 各让位。
2. 要"零依赖可跑" → 放弃 pyyaml/jinja2/图表库，自造受限 YAML 解析器与 SVG 图表。
3. 要"不编造数据" → 放弃联网题的精确数字 ground truth，改用要点 + 来源等级 + 年份三要素判定。
4. 要"可复现" → 放弃 L2（Agent 层回放代理）进 v1.0，先做 L1（评分层回放）。
5. 要"CI 可跑" → 完整 core50 不进 PR 门禁，只做 nightly / 发版门禁；PR 只跑 `smoke` + 已有结果回归。
6. 要"不做单一总冠军" → 报告按能力维度分栏，不产出综合排名分数（《原方案》第 35/45 节）。
