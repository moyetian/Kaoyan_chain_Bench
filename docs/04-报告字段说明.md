# 04 · 报告字段说明

> **English**: [04-报告字段说明.en.md](04-报告字段说明.en.md)

> 面向：读报告的人（任务集工程师、报告/前端工程师、CI 维护者）。
> 上游依据：`docs/01-需求拆解与方案定稿.md` 第 4.8/4.9 节（Metrics / SuiteResult）、第 5.6/5.7 节（报告协议）。
> 状态：与 v1.0 实现一致（`core/reporter.py`、`reporters/*`）。

---

## 1. 产物清单

`kaoyanbench report --suite <id> --agent <name> --tag <tag>` 默认在
`reports/<suite_id>__<agent>__<tag>/` 下产出：

| 文件 | 定位 | 说明 |
|---|---|---|
| `report.json` | **唯一事实源** | 其余格式都由它渲染；程序消费请只读这个 |
| `report.md` | 人读 | 表格化，可直接贴 GitHub |
| `report.html` | 人读 | **单文件、零 CDN、零外部请求**；内联 CSS/JS + 手写 SVG 图表 |
| `report.csv` | 表格 | 每任务一行，便于 Excel（`-f csv` 启用） |

CSV 与 HTML 不会引入 JSON 里没有的信息；任何数值差异以 `report.json` 为准。

---

## 2. `report.json` 顶层结构

```jsonc
{
  "schema_version": "1.0",     // 报告 schema 版本；字段增删会升版本
  "generated_at": "2026-09-23T04:24:17+00:00",
  "benchmark": { "name": "KaoyanBench", "version": "1.0" },
  "suite":   { ... },          // 第 3 节
  "run":     { ... },          // 第 4 节
  "summary": { ... },          // 第 5 节
  "score_breakdown_mean": { ... },  // 第 6 节
  "by_category":   [ ... ],    // 第 7 节
  "by_difficulty": [ ... ],    // 第 7 节
  "errors":  [ ... ],          // 第 9 节
  "tasks":   [ ... ],          // 第 8 节
  "comparison": null           // 第 10 节；未传 --baseline 时为 null
}
```

---

## 3. `suite` 段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | suite ID（如 `core50`） |
| `split` | str | `public` / `private` |
| `task_count` | int | 本次评测的任务数 |
| `seed` | int \| null | 随机种子，复现用 |
| `runs_per_task` | int | 每任务重复次数（决定 Pass@k 是否有区分度） |

---

## 4. `run` 段

| 字段 | 类型 | 说明 |
|---|---|---|
| `agent` | str | 被测 Agent 名 |
| `agent_version` | str \| null | 被测 Agent 版本（回归对比的关键维度） |
| `model` | str \| null | 被测模型名 |
| `tag` | str | 本次运行的标签 |
| `offline_replay` | bool | 是否走了快照离线回放（不发起网络请求） |
| `grader_mode` | str | **`full` / `degraded` / `mixed`**，见第 11 节 |
| `degraded_task_count` | int | 走降级评分（规则化）的任务数 |
| `environment` | obj | `python` / `platform` / `hostname_hash`（哈希，非明文）/ `docker` |

---

## 5. `summary` 段（聚合指标）

`null` 表示**该指标无样本**（不是 0）。跨 tag 对比时 `null` 会让门禁判定为 `skipped`，而不是假装通过。

### 5.1 成功与通过率

| 字段 | 口径 |
|---|---|
| `task_success_rate` | `task_success=True` 的任务数 / 任务总数 |
| `failure_rate` | `1 - task_success_rate` |
| `pass_at_1` | 第 1 次运行即成功的任务占比 |
| `pass_at_3` | 3 次内至少成功 1 次的任务占比（需 `--runs ≥ 3` 才有意义） |

> `task_success` 的判定 = 总分 ≥ `pass_threshold`（默认 60）**且**无 critical check 失败**且**幻觉违规数为 0。

### 5.2 分数

| 字段 | 口径 |
|---|---|
| `score_mean` / `score_median` / `score_p90` | 任务总分的均值 / 中位数 / P90 |

### 5.3 质量维度

| 字段 | 口径 |
|---|---|
| `factuality_mean` | 事实性（要点命中率等） |
| `source_precision_mean` | 来源精确率（引用的来源里符合要求等级的比例） |
| `search_recall_mean` | 检索召回率（要求的来源/要点被找到的比例） |
| `citation_accuracy_mean` | 引用准确率（引用是否真正支持其断言） |
| `hallucination_rate_mean` | 幻觉违规率（命中 `must_not_claim` 的任务占比） |
| `tool_success_rate_mean` | 工具调用成功率 |

### 5.4 效率与成本

| 字段 | 口径 |
|---|---|
| `tool_calls_mean` / `tool_calls_p90` | 工具调用次数 |
| `tokens_mean` / `tokens_p90` | token 消耗（`usage_source != none` 才有值） |
| `latency_seconds_mean` / `_median` / `_p90` | 端到端耗时（秒） |
| `cost_usd_mean` / `cost_usd_total` | 成本（需配置 `pricing`，否则为 null） |

### 5.5 用量可信度

| 字段 | 口径 |
|---|---|
| `usage_missing_count` | 完全拿不到 usage 的任务数（`usage_source=none`） |
| `usage_estimated_ratio` | 其中靠字符数估算（`estimated=true`）的比例 |

> **绝不填 0**：拿不到 token/cost 就是 `null`，并用上面两个字段说明缺口大小。

## 6. `score_breakdown_mean` 段（100 分制 7 维）

```jsonc
{ "factuality": 48.95, "source_quality": 15.51, "citation": 0.78,
  "completeness": 17.35, "tool_execution": 5.2, "task_completion": 2.13,
  "efficiency": 4.96, "total": 94.88 }
```

默认权重（可在 `config/default.yaml` 的 `evaluation.weights` 调整，任务级可覆盖）：

| 维度 | 默认权重 | 满分 |
|---|---|---|
| `factuality` | 0.30 | 30 |
| `source_quality` | 0.20 | 20 |
| `citation` | 0.15 | 15 |
| `completeness` | 0.15 | 15 |
| `tool_execution` | 0.10 | 10 |
| `task_completion` | 0.05 | 5 |
| `efficiency` | 0.05 | 5 |

**中性重分配**：某维度在本任务里没有任何 check 时，其权重按比例转给其余维度（`reallocated`），
避免「搜索题因为没有 planning 检查项而被无端扣分」。因此 `total` 不等于各维度简单相加。

## 7. `by_category` / `by_difficulty` 段

按 8 类 / 4 难度分组的同一组指标：

```jsonc
{ "category": "search", "label": "搜索与信息检索", "task_count": 12,
  "task_success_rate": 1.0, "score_mean": 91.78, "factuality_mean": 1.0,
  "search_recall_mean": 0.78, "source_precision_mean": 1.0,
  "citation_accuracy_mean": null, "hallucination_rate_mean": 0.0,
  "latency_seconds_mean": 0.0, "tool_calls_mean": 0.5,
  "cost_usd_mean": null, "pass_at_1": 1.0, "pass_at_3": 1.0 }
```

`by_difficulty` 同构，键为 `difficulty` / `label`（Easy / Medium / Hard / Expert）。

---

## 8. `tasks[]` 段（任务级明细）

| 字段 | 类型 | 说明 |
|---|---|---|
| `task_id` | str | 任务 ID |
| `category` / `difficulty` / `network` | str | 元信息（`offline` / `online` / `hybrid`） |
| `grader_type` | str | `deterministic` / `semantic` / `hybrid` / `manual` |
| `grader_mode` | str | 本任务的评分模式：`full` / `degraded` |
| `n_runs` | int | 实际运行次数 |
| `pass_at_1` / `pass_at_3` | bool | 本任务的通过情况 |
| `score` | float | 总分（100 分制） |
| `metrics` | obj | 任务级 `Metrics`（见下） |
| `usage_source` | str | `agent_reported` / `usage_file` / `estimated_from_chars` / `none` |
| `checks` | list | 每条 check 的判定明细（见下） |
| `error_codes` | list | 本任务命中的错误码（第 9 节的码表） |
| `trace_ref` | str | 完整 trace 的 JSONL 路径（相对 `results/`） |

`metrics` 字段：`factuality` / `source_precision` / `search_recall` / `citation_accuracy` /
`hallucination_rate` / `tool_success_rate` / `tool_calls` / `tokens` / `latency_seconds` / `cost_usd`。
`null` 表示该任务无对应样本。

`checks[]` 每条：

```jsonc
{ "id": "c1", "type": "numeric", "dimension": "factuality",
  "passed": true, "critical": false,
  "detail": "$.count = 10，期望 eq 10（tol=0）" }
```

- `critical=true` 且 `passed=false` → 该任务 `task_success=False`（一票否决）；
- `detail` 是判定的可读理由，用于人工复核。

---

## 9. `errors[]` 段（错误码聚合）

```jsonc
{ "code": "CITATION_FAILURE", "count": 27, "ratio": 1.0,
  "sample_task_ids": ["HAL-004", "POL-001", "POL-002"] }
```

11 类错误码（方案 4.10）：

`SEARCH_FAILURE` / `SOURCE_SELECTION_FAILURE` / `PARSING_FAILURE` / `TOOL_FAILURE` /
`CITATION_FAILURE` / `HALLUCINATION` / `FORMAT_FAILURE` / `CONSTRAINT_VIOLATION` /
`CALCULATION_FAILURE` / `TIMEOUT` / `UNKNOWN`

`ratio` = 命中任务数 / 任务总数。`sample_task_ids` 只给样例，完整清单看各任务的 `error_codes`。

---

## 10. `comparison` 段（回归章节）

仅在 `report --baseline <tag>` 或 `regression` / `compare` 时非 null：

```jsonc
{
  "baseline_tag": "v2.7.0", "current_tag": "v2.8.0",
  "deltas": [ { "metric": "task_success_rate", "label": "任务成功率",
                "baseline": 0.92, "current": 0.88, "delta_pp": -4.0,
                "delta_abs": -0.04, "ratio": 0.96, "direction": "flat|up|down" } ],
  "gates": [ { "name": "task_success_rate", "label": "任务成功率门禁",
               "metric": "task_success_rate", "threshold_text": "...",
               "delta_pp": -4.0, "result": "pass|fail|warn|skipped" } ],
  "newly_failed_tasks": ["SEARCH-004"],
  "newly_passed_tasks": [],
  "verdict": "pass|warn|fail",
  "verdict_label": "通过|告警|失败"
}
```

门禁规则（`config/default.yaml` 的 `gates`，`absolute` 模式为 Δpp）：

| 门禁 | 默认阈值 | 级别 |
|---|---|---|
| `task_success_rate` | 下降 > 5pp | **fail** |
| `citation_accuracy_mean` | 下降 > 5pp | **fail** |
| `hallucination_rate_mean` | 上升 > 3pp | **fail** |
| `latency_seconds_p90` | 超过基线 ×1.5 | warn |

退出码：`verdict=fail` → 1；`warn` → 0（`--strict-warn` 时为 1）；无基线数据 → 2。
缺样本的指标判定为 `skipped`（**不计入 fail**，也不会被当成通过）。

## 11. `grader_mode` 与可信度（**读报告先看这里**）

`grader_mode` 告诉你这份报告的分数有多少是「语义评测」、多少是「规则化降级」：

| 取值 | 含义 |
|---|---|
| `full` | 全部任务都走完整评分（deterministic 检查 + 语义评测模型） |
| `degraded` | 全部任务都走了规则化降级评分 |
| `mixed` | 部分任务 `full`、部分 `degraded`（看 `degraded_task_count`） |

**降级的触发条件**（`docs/01` 第 5.3 节，写死）：

| 触发 | `degraded_reason` | 行为 |
|---|---|---|
| 无 `GRADER_API_KEY` | `no_api_key` | 规则化评分，结果照常产出 |
| 请求超时 / 连接失败 | `network_unreachable` | 同上 |
| 响应非 JSON / 缺字段 | `invalid_response` | 同上，**最多重试 1 次**（`grader_model.max_retries`） |

降级评分公式（`fallback_semantic_score`）：

```
score = 0.5 × 要点关键词命中率 + 0.3 × required_fields 覆盖率 + 0.2 × 长度/结构合理性
```

**读报告时必须注意**：

1. `degraded` 任务的分数与「语义质量」相关性弱，只反映关键词/字段覆盖率；
2. `summary` 里的均值会混合 `full` 与 `degraded` 两类分数 —— 做版本对比时，
   若两边的 `degraded_task_count` 差异较大，结论不可直接采信；
3. **degraded 结果不得写入回归 baseline**（方案 R9）—— `nightly.yml` 已按此约定做门禁；
4. 报告 HTML 在 `degraded`/`mixed` 时显示红色告警横幅，**绝不静默假装评过**。

## 12. `schema_version` 与兼容性

- 当前为 `"1.0"`。字段**新增**不升版本；字段**重命名/删除/语义变更**会升到 `1.1` / `2.0`。
- 消费方应：只依赖本文列出的字段；遇到未知字段忽略；`null` 一律按「无样本」处理，不要当 0。
- `report.json` 是唯一事实源；`report.md` / `report.html` / `report.csv` 均为派生视图。
