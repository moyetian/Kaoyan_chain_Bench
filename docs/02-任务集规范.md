# KaoyanBench 任务集规范（docs/02）

> 负责人：任务集工程师（T 类）｜依据：`docs/01-需求拆解与方案定稿.md` 第 4/6 章
> 目标：让一位新人**照本文档能独立新增一个任务**，且 `kaoyanbench validate` 零 error。

---

## 1. 目录结构

```
benchmark/tasks/
├── public/                          # 公开集（v1.0 = 50 题）
│   ├── <category>/                  # 8 类目录：search university policy exam pdf planning research hallucination
│   │   └── <TASK_ID>/               # 任务目录，如 SEARCH-001/
│   │       ├── task.json            # 任务定义（必填）
│   │       ├── expected.json        # Ground Truth（可选；外置优先，便于 review）
│   │       ├── references/          # 离线题的 fixture（含 manifest.json）
│   │       │   ├── source_01.html
│   │       │   └── manifest.json    # 文件名 → {sha256, size}
│   │       └── README.md            # 出题人说明（必填，方案 6.5 第 4 条）
└── private/                         # 隐藏集（v1.0 内置 0 题，仅机制）
```

> **快照不在任务目录内**。联网题的网页快照统一放在**运行时快照库**
> `benchmark/snapshots/<TASK_ID>/{index.json,meta.json,pages/<sha256>.html}`
> （由 `config/default.yaml` 的 `evaluation.snapshot_dir` 指定），
> 供 `snapshot verify`、`snapshot fetch` 与 `--offline-replay` 消费。
> `validate` 检查的是这个库，而不是任务目录下的 `snapshots/`。

- `category` 与 `split` **由目录推导**，`task.json` 里写错会 `validate` 报 error。
- 目录名必须等于 `task_id`。

## 2. task.json 字段手册

> 类型/必填/默认以 `core/models.py::Task` 为准。时间字段为 ISO8601；比率为 0.0~1.0。

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `task_id` | str | ✅ | — | 格式 `^([A-Z]+)-\d{3}$`，全局唯一 |
| `category` | str | ✅ | — | 8 类枚举之一，须与目录一致 |
| `difficulty` | str | ✅ | — | `easy`/`medium`/`hard`/`expert` |
| `instruction` | str | ✅ | — | 发给 Agent 的**完整**指令（含输出格式与全部约束） |
| `network` | str | ✅ | `offline` | `offline`/`online`/`hybrid` |
| `time_limit` | int | ✅ | 900 | 秒，>3600 会 warn |
| `tool_limit` | int | ✅ | 60 | 最大工具调用数，>500 会 warn |
| `expected` | object | ✅ | — | Ground Truth，见 §3 |
| `grader` | object | ✅ | — | 见 §4 |
| `split` | str | ❌ | `public` | 由目录推导，写错报 error |
| `tags` | list[str] | ❌ | `[]` | 如 `core`/`smoke`/`long_horizon`/`conflict`/`deterministic` |
| `references_dir` | str | ❌ | `references` | 相对任务目录 |
| `requires_snapshot` | bool | ❌ | false | 联网题是否需要快照 |
| `answer_format` | object | ❌ | `{kind:text}` | `text`/`json`/`file`/`hybrid` |
| `version` | str | ❌ | `1.0` | **gt 变更时必须升版** |
| `title` | str | ❌ | — | 报告展示用短标题 |
| `created_at` | str | ❌ | — | ISO8601 |

### 2.1 answer_format

```jsonc
{ "kind": "text" }                                                  // 自然语言（默认）
{ "kind": "json", "path": "answer" }                                // 要求答案 JSON，path 指出根路径
{ "kind": "file", "filename": "report.json", "schema": { ... } }    // 要求产出文件（file/hybrid 必带 filename）
{ "kind": "hybrid", "text": true, "file": "report.json" }
```

> `kind=file` 时，`file_exists` / `file_json_match` 类 check 会去 **workspace**（含 `output/`）找产出文件。

## 3. expected（Ground Truth）

| 字段 | 类型 | 说明 |
|---|---|---|
| `must_find` | list[Point] | 必须命中的要点 |
| `must_not_claim` | list[str] | **不得断言**的内容（命中即幻觉违规） |
| `required_sources` | list[SourceRequirement] | 来源要求（等级/数量/域名/年份） |
| `required_fields` | list[str] | 答案必须出现的字段（影响 Completeness） |
| `ground_truth` | object \| null | **仅离线 fixture 题**可写精确数字；联网题必须 `null` |

```jsonc
// Point
{ "id": "p1", "weight": 1.0, "dimension": "factuality",
  "any_of": ["初试科目", "考试科目"], "all_of": ["数学一"], "critical": true }

// SourceRequirement
{ "level_min": "E4", "min_count": 1,
  "domain_suffix": [".edu.cn", "chsi.com.cn"], "year": 2026,
  "dimension": "source_quality", "critical": false }
```

### 3.1 ★ Ground Truth 编写硬规则（方案 6.5，必须遵守）

1. **真实院校 + 当年具体数字 → `ground_truth` 必须为 `null`**，只能写 `must_find` 要点 +
   `required_sources`（E4/E5）+ 年份要求 + `must_not_claim`。
2. **fixture 内所有院校/专业/人名/链接必须虚构**（北原大学 / 东岭工业大学 /
   `northplain.edu.example`），文件头写明「虚构数据，仅用于基准测试」。
3. 数字类 `ground_truth` **只允许**出现在 `network=offline` **且有 fixture** 的任务里
   （exam / pdf / UNI-008 / UNI-009 / HAL-* / SEARCH-011/012）。**纯约束题（planning）与无 fixture 的
   离线题请置 `ground_truth=null`**，用 `constraint` check 判定。
4. 每个任务目录必须有 `README.md`：考点、陷阱、为什么这样设 ground truth、更新注意事项。
5. 所有 fixture 必须由 `tools/gen_fixtures.py` **确定性生成**；`references/manifest.json` 记录 sha256，
   `validate` 会校验。

> **两个自动拦截**：`network=online && ground_truth != null` → error；
> `network=offline && ground_truth != null && 缺 references/` → error。

## 4. grader（评分规格）

```jsonc
{
  "type": "hybrid",              // deterministic | semantic | hybrid | manual
  "pass_threshold": 60.0,        // 0~100
  "weights": { "factuality": 0.4, "completeness": 0.6 },  // 可选；覆盖 7 维默认权重，求和须 =1.0
  "checks": [ /* Check[]，见 §5 */ ],
  "rubric": {                    // type 含 semantic 时**必填**
    "prompt_version": "v1",
    "criteria": [
      { "id": "r1", "dimension": "completeness", "weight": 1.0, "question": "……？" }
    ]
  }
}
```

- 7 维：`factuality / source_quality / citation / completeness / tool_execution / task_completion / efficiency`。
- `type=deterministic` 或 `hybrid` 且 `checks` 为空 → `validate` warn（运行时会兜底为 FAIL）。

## 5. 16 种 check 用法手册

> 写在 `grader.checks[]`；**专有参数平铺在同一层**（不要写成 `{"params": {...}}`，虽后端兼容但不推荐）。
> `passed` 三态：`true`/`false`/`null`（null=无法判定，不计分子分母）。
> 通用字段：`id`(唯一)、`type`、`dimension`、`weight`(默认 1.0)、`critical`(未通过则 task_success=false)。

| # | type | 关键参数 | 语义 | 默认 dimension |
|---|---|---|---|---|
| 1 | `point_hit` | `point_id` 或 `any_of`/`all_of` | 要点命中（归一化子串） | factuality |
| 2 | `numeric` | `path`, `op`(eq/ne/gt/ge/lt/le), `value`, `tol` | 数值比对（`tol` 仅 eq/ne 生效） | factuality |
| 3 | `string_eq` | `path`, `value`, `case_sensitive` | 字符串相等 | factuality |
| 4 | `string_contains` | `path`, `value` | 包含 | completeness |
| 5 | `regex` | `path`, `pattern`, `case_sensitive` | 正则搜索 | factuality |
| 6 | `set_includes` | `path`, `values`, `min_hits`（默认全部） | 集合包含 | completeness |
| 7 | `json_schema` | `path`, `schema` | 结构校验 | completeness |
| 8 | `file_exists` | `filename` | 产出文件存在（workspace 或 output/） | task_completion |
| 9 | `file_json_match` | `filename`, `path`, `op`, `value`, `tol` | 产出文件内容比对 | factuality |
| 10 | `year_tag` | `path`, `year`, `require_explicit` | 年份是否显式标注 | source_quality |
| 11 | `source_domain` | `domain_suffix`, `min_count` | 来源域名白名单 | source_quality |
| 12 | `source_level` | `level_min`(E0~E5), `min_count` | 证据等级数量 | source_quality |
| 13 | `citation_coverage` | `min_citations`, `min_supported_ratio` | 引用覆盖与准确率 | citation |
| 14 | `must_not_claim` | `patterns` | **命中即幻觉违规**（critical 强制 true） | factuality |
| 15 | `constraint` | `rules[]`, `answer_path` | 规划/排程约束满足 | task_completion |
| 16 | `evidence_level` | `path`, `expected_min` | 断言是否带 E 级标注 | source_quality |

### 5.1 数据源解析规则

- 多数 check 通过 `path`（JSONPath 子集 `$.a.b[0].c`，见 `utils/text.get_by_path`）取答案数据。
- 默认数据源为 **answer payload**：优先 `raw.parsed/data/answer_json` → `answer.json` 文件 →
  `final_answer` 当 JSON 解析 → 回退 `{"answer": final_answer}`。
- 特殊根：`$.sources` / `$.citations` / `$.search_trace` 指向 Run 的来源/引用/搜索链路。
- `kind=file` 任务的答案在文件里 → 用 `file_exists` / `file_json_match`，**不要**用 `numeric`/`json_schema`
  去读 answer payload。

### 5.2 逐 type 示例

```jsonc
// 1 point_hit —— 也可引用 expected.must_find 的 point_id
{ "id":"c1","type":"point_hit","dimension":"factuality","critical":true,
  "point_id":"p1" }
{ "id":"c2","type":"point_hit","dimension":"factuality","any_of":["学硕"],"all_of":["专业代码"] }

// 2 numeric
{ "id":"c3","type":"numeric","dimension":"factuality","path":"$.count","op":"eq","value":10,"tol":0.0 }

// 6 set_includes
{ "id":"c4","type":"set_includes","dimension":"completeness",
  "values":["081200","085404","081000"],"min_hits":3 }

// 7 json_schema（子集：type/required/properties/items/enum/minimum/maximum/minItems/maxItems/minLength/maxLength）
//   minLength/maxLength 对 array 按**元素个数**、对 string 按**字符数**（含 CJK）判定，array 直接可用；
//   minItems/maxItems 同义（array 元素数）；两者混用时取更严的一侧。
{ "id":"c5","type":"json_schema","dimension":"completeness","path":"$.rows",
  "schema":{"type":"array","minLength":3,"items":{"type":"object","required":["year","total"]}} }

// 14 must_not_claim（必须 critical=true）
{ "id":"c6","type":"must_not_claim","dimension":"factuality","critical":true,
  "patterns":["招生人数为","扩招至"] }

// 15 constraint（规划题核心）
{ "id":"c7","type":"constraint","dimension":"task_completion","critical":true,
  "answer_path":"$.schedule",
  "rules":[
    {"kind":"total_days","op":"eq","value":30},
    {"kind":"daily_total_hours","op":"eq","value":4},
    {"kind":"subject_min_hours","subject":"数学","op":"eq","value":2},
    {"kind":"weekly_rest","op":"ge","value":0.5},
    {"kind":"no_overlap","value":true}
  ] }

// 13 citation_coverage
{ "id":"c8","type":"citation_coverage","dimension":"citation",
  "min_citations":4,"min_supported_ratio":0.5 }
```

`constraint.rules[].kind` 支持：`total_days` / `daily_total_hours` / `subject_min_hours` /
`weekly_rest` / `no_overlap` / `field`{field,op,value} / `assigns_day`{subject,value=日期标签}。
排程结构：顶层可为 `{schedule:[...]}` 或直接数组；每天含 `slots`/`sessions`/`tasks`（`subject`+`hours`
或 `start`/`end`，`start`/`end` 支持 `"8:00"` 或数字小时）。

## 6. 新增一个任务：逐步操作

1. 建目录 `benchmark/tasks/public/<category>/<TASK_ID>/`（`TASK_ID` 与目录同名）。
2. 写 `task.json`：填 §2 字段；离线题在 `expected.ground_truth` 填精确值，联网题置 `null`。
3. 若需要 fixture：把它加进 `tools/gen_fixtures.py` 的 `distribute()`，然后
   `python tools/gen_fixtures.py`（会写 `references/` 与 `manifest.json`）。
   **不要手工创建 references 文件**（会产生不可复现的 hash）。
4. 写 `README.md`（考点 / 陷阱 / ground truth 依据 / 更新注意事项，见 §7 模板）。
5. 若进 smoke 集：加 `tags: ["smoke"]` 并在 `config/agents/mock.yaml` 的 `answers` 段登记预设答案。
6. 验证：`kaoyanbench validate` → error=0；`kaoyanbench run --agent mock --task <TASK_ID> --split public`。
7. 若改动了 ground_truth：提升 `task.json.version`。

### 6.1 用 mock 自测你的 check 是否「诚实」

- **正例**：在 `mock.yaml` 登记一个正确预设答案，`run --agent mock` 应 PASS。
- **反例**：临时改成错误答案（如漏掉 `must_not_claim` 命中的短语），应 FAIL；验证完恢复。
- 见 `tools/gen_fixtures.py` 与 `docs/02` §8 的抽查方法。

### 6.2 反指令泄漏（anti-echo）编写规范

**问题**：若 check 的判定词原样出现在 `instruction` 里，一个只会「回显指令」的 Agent（`--agent echo`，不检索、不计算、不读 fixture）就能命中判定并得分。这会击穿基准的可判别性——分数不再区分「真的做过题」与「抄了题面」。

#### 判定标准（一句话）

> **抄题面能否直接满足该 check 的判定？** 能 → 必须改；不能 → 可以保留。

#### 自动检测

`kaoyanbench validate` 内置 warn 级 anti-echo 检查（不阻断，但必须清零或注明豁免）：

- 仅扫描 `check.type ∈ {string_contains, string_eq, set_includes, point_hit}` 的判定词
  （取 `any_of` / `all_of` / `value` / `values` / `contains` 字段，长度 ≥2 才计入）。
- 命中条件：某判定词**原样**出现在 `instruction` 中 → 报 `grader.checks[i] 的判定词「…」原样出现在 instruction 中`。
- **不被扫描的 type**（`regex` / `json_schema` / `numeric` / `constraint` / `source_level` /
  `evidence_level` / `citation_coverage` / `must_not_claim`）天然免疫，是整改的首选替代形态。

#### 整改三条主要手段

1. **改 instruction（首选）**：用真实用户会问的自然表述，让正确答案必须经**检索/计算/阅读 fixture** 才可得。
   去掉题面里能直接当答案用的判定词。
2. **改 check（次选）**：把「匹配题面出现过的词」换成「匹配答案中才应有的实质信息」。优先级：
   `numeric` / `json_schema` / `file_json_match` / `constraint` / `citation_coverage` / `source_level`
   ＞ `regex`（用锚尾或跨段 `[\s\S]*`）＞ 扫描型（`string_contains` / `point_hit` 等）。
3. **保留必要题面信息**：题目本身必须交代的约束（如「每天 6h、政治≥0.5h」）不算泄漏——
   判断只看「抄题面能否直接满足判定」。若某判定词确实必须在题面出现，则在任务 `README.md`
   的「更新注意事项」里注明豁免理由。

#### 正 / 反例

```jsonc
// ✗ 反例：instruction 含「取消复试」，c1 直接匹配该词 → echo 命中、白得分
"instruction": "材料里有没有取消复试的信息？",
{ "id":"c1","type":"string_contains","value":"取消复试" }

// ✓ 正例（改 check）：判定「答案里出现的生效年份」，题面不泄露年份语义
{ "id":"c1","type":"regex","path":"$.answer","pattern":"2026" }

// ✓ 正例（改 instruction）：题面只留任务目标，判定词必须读 fixture 才能得出
"instruction": "把这份招生简章里对考生影响最大的变化摘出来，给出生效年份。",
{ "id":"c1","type":"point_hit","point_id":"p1" }   // p1 在 expected.must_find 中，题面不出现
```

#### 验收红线

- `validate --suite core50` 的 anti-echo warn **≤15**（保留项须在任务 README 注明理由）。
- `run --suite core50 --agent echo` 通过率 **≤8%**（即最多 4/50）。
- 同时 `run --agent mock` 仍须 **≥90%**（改 check 后必须同步更新 `config/agents/mock.yaml` 预设答案）。

## 7. README.md 模板

```markdown
# <TASK_ID> —— <一句话标题>
- 类别：`<category>`；难度：`<difficulty>`；网络：`<network>`；评分：`<grader.type>`
- tags：`core`、`deterministic` …

## 考点
<instruction 摘要：这道题要测什么能力>

## 陷阱
- 不得断言：……（命中即幻觉违规）。
- （联网题）涉及真实院校时不得编造当年精确数字。
- （离线题）只依据本地 fixture 作答。

## 为什么这样设 Ground Truth
（联网题）按 6.5 硬规则 ground_truth=null，用 must_find + required_sources + 年份 + must_not_claim 判定。
（离线题）ground truth 由 tools/gen_fixtures.py 确定性生成，manifest.json 记录 sha256。

## 更新注意事项
- 变更 fixture 后重跑 tools/gen_fixtures.py，manifest.json 同步更新。
- 变更 ground_truth 必须提升 version。
```

## 8. 自检清单

- [ ] `kaoyanbench validate` 在全部任务上 **error=0**。
- [ ] `task_id` 唯一且格式合规；目录名、category、split 三者一致。
- [ ] 联网题 `ground_truth` 为 `null`；离线数字题有 `references/` 且 hash 对得上。
- [ ] **anti-echo**：`validate` 的 anti-echo warn 为 0（或 ≤15 且已在 README 注明豁免）；`run --agent echo` 通过率 ≤8%（见 §6.2）。
- [ ] `must_not_claim`：既在 `expected.must_not_claim`，也有对应的 `must_not_claim` check（`critical=true`）。
- [ ] `point_hit` 若用 `point_id`，该 id 必须存在于 `expected.must_find`。
- [ ] `grader.weights`（若写）求和 =1.0；`rubric.criteria` 非空（semantic/hybrid）。
- [ ] 每个任务目录有 `README.md`。
