## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Linux / macOS / Windows | 已实测 Linux（Ubuntu） |
| Python | ≥ 3.10 | `pyproject.toml: requires-python = ">=3.10"`，CI matrix 覆盖 3.10/3.11/3.12 |
| 运行时依赖 | **无第三方依赖** | 核心链路纯标准库；`pip install -e .` 不拉任何包 |
| 可选依赖 | `pyyaml`、`fpdf2`、`openpyxl` | 仅 `pyyaml` 用于完整 YAML 兜底解析；`fpdf2/openpyxl` 用于 fixture 增强生成（缺失时 fixture 生成器自动降级，见 T-01） |
| 磁盘 | 建议 ≥ 500MB 空闲 | `results/workspaces` 会随运行增长；CI 每次清理 |
| 网络 | **离线可跑** | validate / smoke / core50(mock) 全程不联网；联网题需快照或真实网页 |

## 4. ★ 安装错位检测与修正（本次部署重点）

**背景**：本机 `pip install -e .` 曾指向上游验证副本 `/tmp/kybcheck`；现应指向 `/workspace/KaoyanBench`。
editable 安装会把「项目路径」写进 site-packages 的 `.pth` / `__editable__` 文件，一旦在错误目录安装，
`kaoyanbench` 命令实际加载的是**另一个副本的源码**，会产生「改了代码不生效」或「版本/行为不一致」的诡异现象。

### 4.1 检测

```bash
# ① 看模块实际加载路径（最直接）
python3 -c "import kaoyanbench; print(kaoyanbench.__file__)"
#   正确：/workspace/KaoyanBench/src/kaoyanbench/__init__.py
#   错误：/tmp/kybcheck/src/kaoyanbench/__init__.py  ← 安装错位

# ② 看 pip 记录的 editable 位置
python3 -m pip show kaoyanbench | grep -i "location\|editable"
#   应有：Editable project location: /workspace/KaoyanBench

# ③ 看命令解析到的可执行文件
which -a kaoyanbench kyb

# ④ 交叉核对：版本 + 根目录
kaoyanbench --version
python3 -c "from kaoyanbench.core.config import find_project_root; print(find_project_root())"
```

### 4.2 修正

```bash
# 先卸载错位的安装
pip uninstall -y kaoyanbench

# 确认在正确目录后重装
cd /workspace/KaoyanBench
pip install -e .

# 再验证
python3 -c "import kaoyanbench; print(kaoyanbench.__file__)"
# 期望：/workspace/KaoyanBench/src/kaoyanbench/__init__.py
```

> 若 `pip show` 仍显示 `/tmp/kybcheck`，检查是否有残留的 `.pth`/`__editable__*.pth` 指向旧路径，
> 或使用了 venv/pyenv 不同解释器——用 `python3 -m pip ...`（而非裸 `pip`）确保装到同一解释器。

## 5. 生成 fixtures（确定性、离线）

smoke 的 6 题由 fixture 驱动。fixture 由 `tools/gen_fixtures.py` **确定性生成**（连跑两次聚合 sha256 一致）。

```bash
cd /workspace/KaoyanBench
kaoyanbench fixtures build             # 调用 tools/gen_fixtures.py
# 校验现有 fixtures（manifest 内文件存在且 sha256 匹配）
kaoyanbench fixtures check             # 期望：fixtures 校验通过 ✅
```

> `fpdf2` / `openpyxl` 缺失时，fixture 生成器会走内置最小 PDF 生成器、Excel 降级为 CSV 并告警（T-01 设计），
> **不会失败**。如需完全一致地复现 PDF/XLSX fixture，建议 `pip install -e ".[fixtures]"`。

## 8. 完整 core50（夜间 / 发版门禁，**不进 PR 门禁**）

> R5：research 类单题上限 900s，50 题 × 3 次串行理论上限 12.5h。**完整 core50 只做 nightly / 发版门禁**。

```bash
# 离线 mock 全量（零网络，用于验证完整 pipeline + 报告 + gate）
kaoyanbench run --suite core50 --agent mock --tag core-mock --concurrency 4
kaoyanbench report --suite core50 --agent mock --tag core-mock -f json,markdown,html,csv
```

接入真实 Agent（示例：kaoyan_chain）：

```bash
export OPENAI_BASE_URL=...   # 见第 10 节
export OPENAI_API_KEY=...
kaoyanbench run --suite core50 --agent kaoyan_chain --tag v2.8.0 --runs 3 --concurrency 3
```

## 9. 回归门禁（regression）

```bash
# 两个 tag 必须都已 run 过（同 suite / 同 agent）
kaoyanbench regression --baseline v2.7.0 --current v2.8.0 --suite core50
```

退出码：`0` pass / `1` gate fail（CI 必须判失败）/ `2` 运行错误。

Gate 阈值（`config/default.yaml: gates`，方案第 33 节）：

| 指标 | 阈值 | 级别 |
|---|---|---|
| `task_success_rate` | 下降 > 5pp | fail |
| `citation_accuracy_mean` | 下降 > 5pp | fail |
| `hallucination_rate_mean` | 上升 > 3pp | fail |
| `latency_seconds_p90` | 相对基线 > 1.5× | warn |

## 10. 环境变量清单（已逐一核实存在）

> **只列变量名与用途，绝不写真实值。** 变量名为代码/配置中实际存在的（核实见文末）。

| 变量名 | 必填 | 用途 | 代码/配置引用 |
|---|---|---|---|
| `KAOYANBENCH_ROOT` | 否 | 指定项目根（否则向上查找 `pyproject.toml`） | `core/config.py:117`、`cli.py:165` |
| `KAOYANBENCH_HOST_SALT` | 否 | 主机名哈希盐（隐私，不落盘真实主机名） | `utils/hashing.py:11` |
| `KAOYANBENCH_REPLAY_DIR` | 否 | L2 Agent 层回放目录（预留，P2） | `core/workspace.py:207`、`snapshot.py:13` |
| `KAOYANBENCH_USAGE_FILE` | 否 | Agent 上报 token/cost 的 JSON 路径（框架注入子进程） | `core/workspace.py:224` |
| `KAOYANBENCH_ANSWER_FILE` | 否 | Agent 答案文件路径（框架注入子进程） | `core/workspace.py:223` |
| `OPENAI_BASE_URL` | 否* | 被测模型 base_url（`${OPENAI_BASE_URL:-}` 插值） | `config/default.yaml:21`、`runners/http.py` |
| `OPENAI_API_KEY` | 否* | 被测模型 key（`model.api_key_env` 默认值） | `config/default.yaml:22` |
| `GRADER_BASE_URL` | 否* | 评测模型 base_url（`${GRADER_BASE_URL:-}` 插值） | `config/default.yaml:28` |
| `GRADER_API_KEY` | 否* | 评测模型 key（`grader_model.api_key_env` 默认值） | `config/default.yaml:29` |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_BASE_URL` | 否 | claude_code Agent 透传 | `config/agents/claude_code.yaml:21-22` |
| `WORKBUDDY_BASE_URL` / `WORKBUDDY_API_KEY` | 否 | workbuddy Agent 端点与 key | `config/agents/workbuddy.yaml:10-11` |

\* 「否」= 只跑离线 smoke/validate 一个都不需要；仅真实语义评测/接入真实 Agent 时设置。
无 `GRADER_API_KEY` 或 `GRADER_BASE_URL` 时，Semantic Grader 自动进入 `grader_mode=degraded`（**不静默假装评过**）。

完整示例见仓库根 `.env.example`。

## 11. Docker 用法

项目**零运行时依赖**，镜像应保持精简。仓库提供 `Dockerfile`（基于 `python:3.11-slim`）：

```bash
# 构建
docker build -t kaoyanbench:1.0.0 .

# 校验任务集（离线）
docker run --rm kaoyanbench:1.0.0 kaoyanbench validate --suite core50

# 跑烟雾（离线）
docker run --rm kaoyanbench:1.0.0 kaoyanbench run --suite smoke --agent mock --tag docker-smoke

# 挂载宿主 results / reports 以保留产物
docker run --rm -v "$PWD/results:/app/results" -v "$PWD/reports:/app/reports" \
  kaoyanbench:1.0.0 kaoyanbench run --suite smoke --agent mock --tag docker-smoke

# 需要语义评测时通过环境变量传入（切勿写进镜像）
docker run --rm -e GRADER_BASE_URL -e GRADER_API_KEY kaoyanbench:1.0.0 \
  kaoyanbench validate --suite core50
```

### 沙箱隔离级别（如实描述，方案 R10）

- **v1.0 的隔离级别是「进程级」**，不是容器级、更不是内核级。
- 具体措施（`core/sandbox.py`）：独立 workspace；env 白名单（`env_passthrough=[]` 时**不向子进程透传任何 `*_API_KEY`**）；`HOME/TMPDIR/XDG_CACHE_HOME` 重定向到 workspace；超时 SIGTERM → 宽限 → SIGKILL。
- **不能防**：子进程写 `/tmp` 之外的路径、网络外泄。
- `runtime.docker.enabled=true` 在 v1.0 **未实现**（P2 占位），设置后会显式报错 `DockerNotAvailableError`，而非静默降级。
  本文的 Dockerfile 是「把 CLI 打包进容器」的部署手段，**不等于** Sandbox 的 Docker 隔离功能。

## 12. 常见故障排查

### 12.1 安装错位（改了代码不生效 / 版本对不上）
见第 4 节。核心命令：`python3 -c "import kaoyanbench; print(kaoyanbench.__file__)"`。

### 12.2 无 api_key 导致 degraded
- 现象：报告顶部有 degraded 红色告警；`grader_mode=degraded`；`degraded_reason=no_api_key`（或 `network_unreachable` / `invalid_response`）。
- 原因：未设置 `GRADER_BASE_URL` / `GRADER_API_KEY`，或二者为空。
- 处理：① 需要真实语义评测 → 设置这两个变量；② 只用离线确定性评分 → 可忽略（确定性 check 仍正常工作）。
- **★ R9：`grader_mode=degraded` 时不得写入回归 baseline**，否则污染基线（CI 已强制）。

### 12.3 联网题失败 / `needs_snapshot`
- 现象：`validate` 对 23 道 online 题报 `requires_snapshot` 告警（warn，非 error）；运行时报找不到快照。
- 原因：**23 题的快照尚未建立（T-07 遗留，需联网）**；v1.0 只交付快照机制与 L1 回放。
- 快照库位置：`benchmark/snapshots/<TASK_ID>/`（即 `evaluation.snapshot_dir`）。
  `tools/gen_fixtures.py` 会为 SEARCH-011 / SEARCH-012 / RES-002 生成**本地固定假快照**（绝不联网），
  因此这三题可直接 `kaoyanbench snapshot verify --task all` 通过，并可用 `--offline-replay` 走 L1 回放。
- 处理：① 离线场景只跑离线子集（smoke / 确定性题）；② 建快照需联网：`kaoyanbench snapshot fetch --task SEARCH-004 --url <URL>`，再 `kaoyanbench snapshot verify`；③ 用 `--offline-replay` 走本地快照回放（不发起任何网络请求）。
- **不要假装覆盖**：联网题的真实端到端语义评分在无网/无快照时**未覆盖**。

### 12.4 超时（research 类长任务）
- 现象：任务 `timed_out=true`、`exit_code=-15`、`errors=[PARSING_FAILURE, TIMEOUT]`；任务计 FAIL 但**不丢失**。
- 处理：`--time-limit N` 覆盖单题上限；或调低 `--concurrency`（默认 1）避免资源竞争；nightly 才跑完整 core50。

### 12.5 `validate` 退出码非 0
- `2`：存在 error 级 issue（schema / fixture hash 不匹配 / ground_truth 违规）——必须修复。
- `1`：仅在 `--strict` 下，warn 也算不通过（默认 warn 不阻塞）。

### 12.6 SQLite 相关
`results/benchmark.db` 是**派生物，可随时 `rm` 重建**（`store.rebuild_db()`）。若数据库损坏：`rm results/benchmark.db` 后下次查询会自动 `sync_db` 从 JSONL 重建。

## 13. 一键上线前检查

```bash
bash tools/release_check.sh
```

共 8 步：安装与版本 → pytest → `validate` → `fixtures` → 离线冒烟 → 报告生成与产物存在性
→ HTML 报告验收 → 回归门禁；任一失败脚本退出码非 0。

非 Unix 环境（如 Windows Git Bash）或未执行 `pip install -e .` 时，可用环境变量覆盖解释器与 CLI 入口：

```bash
PY=py KYB="py -m kaoyanbench" PYTHONPATH=src bash tools/release_check.sh
```

详见 `docs/07-上线检查清单.md` 与 `docs/08-回滚预案.md`。
